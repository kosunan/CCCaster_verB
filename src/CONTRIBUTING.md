# はじめに

この `CONTRIBUTING.md` では、CCCaster_v10 プロジェクトに参加するすべての開発者（AIエージェントを含む）が守るべき共通のルールと開発フローを定めます。
本プロジェクトはロールバック通信という極めて高いパフォーマンスと精度が求められる領域を扱うため、厳格な変更管理とアーキテクチャの遵守が必要です。

## 1. 開発の基本理念（絶対の戒律）

1. **「対戦にかかわる処理はすべてゲーム内（インゲーム）で行う」**
   - パフォーマンスや実行速度に直結する同期処理（Rollback Engine）、SaveState/LoadState等のメモリ読み書きは、プロセス外から低速なツールを使わず、DLLフックを通じて必ずゲーム内部の同じメモリ空間で処理させます。
2. **「妥協なきチューニングの徹底」**
   - 処理の遅延やフレームドロップを招く非効率な設計（無駄なコピーや不要なロック待機）を行ってはいけません。
3. **「アーキテクチャの変更判断」**
   - 新規機能を実装する際、あるいは上記チューニングが難しい構造上の壁にぶつかった場合は、独断で迂回措置を取らず、影響範囲を明確にしたうえでマスター（レビュワー）に相談してください。

## 2. コミット・変更履歴のルール

1. **Atomic Commit**: コード変更と `changelogs/CHANGELOG_YYYY-MM.md` の追記は同一コミットに含める。
2. **見出しの一致**: コミットメッセージ1行目と changelog の見出しを一致させる。
3. **月別ファイル管理**: changelog は月ごとに分ける（例: `changelogs/CHANGELOG_2026-03.md`）。

### changelog に書くこと / 書かないこと

changelog は **「なぜそうしたか」** を残す場所です。**5〜15行**を目安にしてください。

| 書く | 書かない |
|---|---|
| なぜその判断をしたか | 変更ファイルの一覧（`git show --stat` で出る） |
| 検討して**採らなかった**案とその理由 | 差分の説明（`git diff` で読める） |
| 後から見て意外に思われる決定 | 測定値・ログ・実験の詳細 |
| 既知の未解決事項 | 表・手順・網羅的な解説 |

**測定値・調査結果・設計の詳細は `docs/design/` に書いてください。** changelog に長い表や実測データを貼ると、git 履歴と三重に重複して読む場所が分からなくなります。

判断理由が自明な変更（誤字修正、機械的なリネーム等）は、見出し1行だけで構いません。

## 3. ファイル管理とワークスペースの浄化

- **ビルド出力とログ**: ビルド成果物・ログファイル（`*.log`, `*.txt`）をプロジェクトルートに放置することは厳禁です。実行ログやビルドエラーは必ず `build_logs/` に隔離されるようスクリプトやパイプを調整してください。
- **一時スクリプト**: 調査用の一時スクリプト（Python, PowerShell等）はコミット対象に含めず、`.ai_workspace/` 等の無視ディレクトリ内で実行・破棄してください。

## 4. 設計と実装のワークフロー

1. 新しい機能を開発する前には、必ず `docs/design/` 配下に設計書を作成、または関連する要件定義書（`docs/requirements/`）を更新してください。
2. その後、設計に基づき `src/` 配下（`core_dll`, `main_app`, `launcher` など適切なレイヤー）に実装を行います。
3. 実装と設計が乖離した場合は、ソースコードだけでなく必ず設計書側も修正して同期させてください。

これらの規約は、システムが長期的に高品質を維持し、開発者間で共通の理解を持つためのものです。
ご不明な点がある場合は、Issue等で議論を行ってください。
