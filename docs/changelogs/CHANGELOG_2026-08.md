# fix: コントローラ設定 UI が割り当てを取りこぼしていた

## 2026-08-13

入力が届かない件を直したあとも、UI 側に「設定したのに保存されない」経路が3つ残っていた。
どれも単独で「設定が効かない」を再現できる。

**F4 で閉じるとバインドが黙って捨てられていた。** `OnClose()` が
`ResetBindingState()` → `SaveDeviceAllocations()` の順で呼んでおり、前者が `binds[]` を
空にするだけで `SaveBinds()` を通らなかった。デバイス割当だけは保存されるので、
「デバイスは設定されているのに操作が効かない」という最も分かりにくい形になる。
保存する側に倒し、あわせて `SaveBinds()` は**空のバインドを書かない**ようにした。
空＝そのセッションで到達しなかった項目なので、既存値を消さずに済む。
黙って捨てるのだけは避けた。UI にも `[F4] Save and Close` と明記した。

**設定画面を開いて閉じるだけで割当が消えていた。** `s_pXJoyId` は起動時 `-1` 固定で、
保存済みの `P1Device` / `P2Device` から復元する処理が無かった。その状態で開閉すると
`SaveDeviceAllocations()` が空文字で上書きする。復元と、未割当時に既存値を潰さないことの
**両方**を入れた。片方だけでは別の穴が残る。
ただし「未割当なら書かない」だけにすると、デバイスを P1 から P2 へ移したときに古い
`P1Device` が残って次回起動で両スロット同じデバイスになる。そこで
「反対スロットに入ったことが確認できるときだけ消す」規則にした。

**設定ファイルのパスが相対パスのままだった。** 読み手側は絶対パス化済みだったので、
書き手も `paths::Resolve()` に通した。ここが揃っていないと、書けているのに読めない。

`Up_Alt` 等（読み手にしか存在しないキー）は、ジョイスティックの ini に**既定値と同じ値を
実体化して書き出す**だけにした。挙動は変わらないが、値がファイルに見えるので手編集で
解除・変更ができる。UI 項目を13→17に増やす案は却下した。このウィザードは項目を
スキップできないため、アナログスティックの無いレバーで設定を完了できなくなる。
恒久対応はスキップ操作を用意してからになる。

なお `ui/ControllerMapper.cpp` は `Controller_Ui_Logic.cpp` とほぼ同一の**到達不能な重複実装**で、
今回も触っていない。次に同じ場所を直す人が確実に踏むので、削除を別途行うべき。

# fix: コントローラ設定がゲームに一切届いていなかった

## 2026-08-13

「キャラセレでキー入力が効かない。設定画面でのアサインは反応するのに、ゲームに反映されない」
という報告の原因。**独立した2つのバグが重なっており、どちらか片方だけ直しても症状は消えない。**

## 1. DLL プロセスが設定ファイルを一度も読んでいなかった

`ConfigManager::configData` は static メンバ、つまり**プロセスごとに1つ**。
`ConfigManager::Load()` の呼び出しはリポジトリ全体で `cli_launcher/main.cpp` の1箇所しかなく、
これはランチャー EXE のプロセスだった。DLL は `LoadLibraryA` で注入される別プロセスなので、
ランチャーが読んだ内容は一切来ない。

結果、`GetString("Settings","P1Device")` は ini に何が書いてあっても常に `""` を返し、
`GetJoyIdFromDeviceName("")` が `-1`、`BuildPlayerInput(-1, …)` が**無言で 0** を返し、
その 0 が毎フレーム `GC::WriteInput` でゲームメモリに書き込まれていた。
`MbaaPatcher` がゲーム自身の入力読み取りを潰しているためフォールバックは無く、
**入力が「効きにくい」ではなく「完全に効かない」**という質感になっていたのはこのため。

設定画面だけ反応したのは、そちらが `ImGui::IsKeyPressed()` と
`DirectInputHook::GetAnyInputEdge()` を直接読んでおり `ConfigManager` を通らないため。
**「設定できるのに効かない」という症状は、この非対称がそのまま出たもの。**

あわせてパスを DLL 基準の絶対パスに統一した（`common/DataPaths.hpp`）。
従来の `"cccaster\\xxx.ini"` はゲームのカレントディレクトリ基準で、ゲーム側が
`SetCurrentDirectory` を呼べば書き手と読み手が別の場所を指しうる。しかもその食い違いは
「設定が効かない」としか現れない。ログは既に DLL 基準に直してあったので、同じ場所に寄せた。
実機のパスは従来と同じ `<ゲーム>\cccaster\` を指すので、既存の ini の移行は不要。

## 2. `P1Device` / `P2Device` の意味が UI と読み手で食い違っていた

| | 意味 |
|---|---|
| UI（`Controller_Ui_*`） | 画面左が P1、右が P2 ＝ **ローカルの座席** |
| 読み手（`SceneRunner`） | `isHost ? P1 : P2` ＝ **ホスト機 / クライアント機** |

クライアント機の人は自分を「1P」と認識して左に割り当てるが、読み手は `P2Device` を見る。
`_TEST_MBAACC` の ini が実際にこの形になっていた。

| 機体 | ini | 読むキー | 結果 |
|---|---|---|---|
| MBAACC_1 (host) | `P1Device=` (空) / `P2Device=Keyboard` | `P1Device` | 空 |
| MBAACC_2 (client) | `P1Device=Keyboard` / `P2Device=` (空) | `P2Device` | 空 |

**両機とも「読むほうが空」。** キーバインド自体（`Keyboard.ini`）は正しく保存されていた。

`GetLocalPlayerInput(isHost, soloLocal)` を追加し、ネットプレイでは
「割当スロットが空ならもう一方をローカルデバイスとみなす」ようにした。
ネットプレイのローカルプレイヤーは1人なので、どちらに入っていてもそれがローカルデバイスで正しい。
オフライン（Training 等）は2人ともローカルなので、この読み替えはしない。

UI 側の意味づけを変える案もあったが、既存 ini を壊すうえ、
**どちらに割り当てても動くほうが利用者に事故が起きない**と判断した。

## 3. 無言の失敗をやめた

この2つが長く残ったのは、どちらも**ログにも UI にも何も出さずに 0 を返していた**ため。
デバイス解決に失敗している間は状態が変わったときに1回ログを出すようにした。
「入力が効かない」ときに最初に見る場所を作るのが目的で、毎フレーム出しては意味がない。

# perf: ログの毎行 fopen/fclose をやめ、計測を汚染しないようにした

## 2026-08-13

`HookLog` は1行ごとに `fopen`/`fprintf`/`fclose` を**排他なしで**実行していた。
これを叩くのは通信スレッド（受信パケットごと＝60Hz以上）とゲームスレッド（MEM_TRACE 時は
毎フレーム）の2本で、(a) 行が混線して読めない、(b) 同期ファイル I/O がフレームタイミングを
汚染する、の二重の実害があった。**これから測る値の土台なので、同期の改修より先に潰す。**

ファイルは開きっぱなしにし、書き手はロック下でキューに積むだけにした。書き出しは専用スレッドが
条件変数で起きて行う。周期タイマーではなく通知駆動にしたのは、`TimeHooks` が
`QueryPerformanceCounter` を 1000 倍速でフックしており、`wait_for` の時間基準が汚染されて
最悪ホットスピンするため。通知駆動なら時計に一切依存しない。

**非同期化はクラッシュ時のログ欠損と引き換え**になる。このツールでログを読む主目的が
クラッシュ調査であることを考えると、そのままでは機能後退になる。そこで
`Disconnected` / `Aborted` / `[FATAL]` / `[ASSERT]` を含む行だけは呼び出しスレッドで
書き切る。前2つを入れたのは、実際に `SceneRunner::Step()` が終了直前に出す文字列で、
かつ**その直後に `TerminateProcess` でワーカーごと消える**ため。
致命的なログを新設するときは、この判定に載る文字列を含めること。

`Shutdown(blocking=false)` は `ExitProcess` 経路用で、他スレッドがミューテックスを
握ったまま消えている前提のものだが、`fileMutex` しか `try_lock` にしておらず
キュー側で待ってしまっていた。DllMain 内＝ローダーロック保持中に待つと
プロセスが終わらなくなるため、両方 `try_lock` に揃えた。

Win32 専用 API は使っていない（`<mutex>`/`<thread>`/`<cstdio>` のみ）。パス解決だけは
`GetModuleFileNameA` が要るので `dllmain.cpp` 側に残し、`SetLogPath()` で注入する。

# build: harness と単体テストを Linux でも動くようにした — 検証を実機から切り離す

## 2026-08-13

これまで、同期ロジックを1回検証するのに Windows・実ゲーム2窓・GUI が必要だった。
harness も Windows 専用でしか動かず、実機に触れない状態では**コンパイルが通るかどうかすら
確認できなかった**。今後の作業はフレーム空間の作り直しで、試行回数がそのまま速度になる。
先に検証の敷居を下げた。

OS 依存処理の窓口を `common/Platform.hpp` 1枚に集約し、`windows.h` を叩いていた箇所を
そこへ寄せた。`#ifdef _WIN32` を各所に撒かなかったのは、撒くと「Linux では通るが Windows では
違う経路」が静かに増えるため。窓口が1つなら差分はそのファイルを読めば全部分かる。

`SleepMs()` と `RealSleepMs()` を分けたのは、実機では `TimeHooks` の SleepBypass によって
`Sleep(1)` が `Sleep(0)` に化けるという**既存の挙動を変えないため**。既存の呼び出しは前者に
対応させ、挙動は現状のまま据え置いた。CPU を返す修正（AUDIT A-4）は別の変更として行う。
1つのコミットで2つのことをすると、デシンクの再現が変わったときにどちらが原因か分からなくなる。

集約したついでに、時刻計算のオーバーフローを直した。`QPC * 1000000 / freq` は
乗算が先に溢れるため、10MHz の QPC では**約10.7日で符号付きオーバーフロー**する。
商と剰余に分けた。元は `WasapiClock` にあったもので、集約により全時刻取得の
単一経路になったため、ここで潰しておく必要があった。

WASAPI は `#ifdef` で切り、Linux では単調時計に落ちる。これは元々「オーディオデバイスが無い
ヘッドレス環境」用に用意されていた経路で、Linux のために新設したものではない。ただし
ドリフト特性は別物なので、**Linux の harness はクロック品質の検証には使えない**。

`IpcManager` は Linux 版を no-op にした。呼び出し側（`SceneRunner`）に `#ifdef` を入れると
処理順が OS で変わるので、受け側で吸収する。IPC の相手は Windows 専用の CLI ランチャーであり、
Linux で本当に必要になったら shm_open で実装する。

`run_pair.sh` は `run_pair.ps1` と判定・出力形式を意図的に揃えた。物差しが違うと
「Linux では OK だが実機では NG」の切り分けができなくなる。

Linux ネイティブの harness で、実機由来のデシンク（`WT` が netFrame=231 付近で分岐）が
Windows harness と同じ形で再現することを確認済み。

# build: 64bit ビルドを止め、対象 Windows バージョンを固定した

## 2026-08-13

`AGENTS.md` が落とし穴の筆頭に「32bit 限定」を挙げていながら、ビルドシステム側では
何も防いでいなかった。64bit でも DLL は生成でき、注入だけが**無言で**失敗するため、
症状から原因に辿り着けない。configure の時点で落とす。

`_WIN32_WINNT` はこれまでツールチェイン既定値任せだった。MSYS2(GCC15, 既定 Win10) では
通るが、既定が古いツールチェインでは `inet_pton` / `inet_ntop` が未宣言になる。
どの環境でも同じ API 集合が見えるよう Windows 7 に固定した。ここを上げると
古い環境で動かなくなるので、上げる場合は理由を書くこと。
