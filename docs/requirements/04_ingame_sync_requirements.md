# 04 In-Game Sync Requirements (インゲーム同期要件)

## 1. 概要
ゲームプロセス (MBAA.exe) に DLL をインジェクトした後の、ゲーム空間内での状態遷移と各フェーズにおける同期ルールを定義します。

## 2. 同期フェーズ (Sync Phases)

対戦の進行状況に応じて、厳密なフェーズ分けを行い、状態の不整合（Desync）を防ぎます。

### 2.1 Character Select (キャラセレ)
- **概要**: プレイヤーがキャラクターやスタイルを選択する画面。
- **要件**:
  - ロールバックエンジンは**無効**。純粋なディレイベース（または Lock-step）での入力同期を行う。
  - 両者が「Loading」へ遷移するまで、入力パケットを等速で交換し続ける。

### 2.2 Loading (ロード画面)
- **概要**: キャラクター選択後〜ラウンド1開始までのデータ読み込み区間。
- **要件**:
  - 先にロードを終えた側は、相手のロード完了（または「InGame」への遷移準備完了シグナル）を待機する。
  - 暗転抜け直後のズレを防ぐため、このフェーズ中にバックグラウンドで `TimeSynchronizer` を起動し、互いのクロック（PC内の高精度タイマー）に対する推定オフセット θ を計算・確定させる。

### 2.3 Ready & Round Start (ラウンド開始)
- **概要**: Loading終了後、実際の対戦フレームのカウントアップが始まる瞬間。
- **要件**:
  - `TimeSynchronizer` で確定したオフセット値をもとに、両者の Frame 0 を同時に発火させる。これを便宜上 **Big Bang Sync** と呼称する。

### 2.4 InGame (対戦中)
- **概要**: 操作が有効な対戦アクション中のフェーズ。
- **要件**:
  - ロールバックエンジンが**有効**。
  - 毎フレーム、自身のローカル入力をDirectInputフック経由で横取りしてUDP送信しつつ、相手からの入力を待ち受ける。
  - 相手の入力到着が想定時間（自機の現在フレーム＋通信片道遅延）より遅れた場合、過去に入力された最新のキーを「予測（Predict）」としてゲームエンジンに渡し、フレームを進める。
  - 遅れて正しい入力が到着した際、予測と異なっていた場合はゲームの「Save State」をロードして過去に巻き戻し、正しい入力から現在フレームまで「Rollup（再計算・早送り）」を行う。

### 2.5 Rematch / Return to Select
- **概要**: 対戦終了後、再戦（Rematch）またはキャラセレへ戻る状態。
- **要件**:
  - この状態への移行を検知した際、ロールバックエンジンの状態（Save Memory等）をクリア・初期配置にリセットし、再び 2.1 (Character Select) のフェーズからやり直す準備を整える。

## 3. クロック同期と漂流（Drift）補正

- PCのハードウェアタイマーは個体差により1秒の長さが微妙に異なる（Clock Drift）。
- 対戦時間が伸びるにつれ、片方のFrameは60.01 FPS、もう片方は 59.98 FPS のようにズレが生じていく。
- `VirtualClock` システムを用い、定期的に OWD (One-Way Delay) の偏りを計算し、ローカルの1フレームの待機時間（通常16.666ms）を動的に伸縮させて、両者のクロックを常に一致させるように自動補正（Slew）を行うこと。
