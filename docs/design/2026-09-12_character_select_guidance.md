# キャラクター選択の設定案内と遅延警告

## 表示方針

- キャラクター選択画面のHUDは下端2行に固定する。
- 1行目はコントローラ設定を最優先し、キャラクター決定前にF4を開くことを常時表示する。
- F4を閉じた後は「保存した設定で移動・決定を試す」案内を10秒維持する。その後はF4案内へ戻り、案内自体は消さない。
- 2行目は通常時にRTT、Jitter、D、R、1Fと設定キーを表示する。設定同期中・不採用時は状態文、D+R超過時は遅延警告へ差し替える。
- 対戦中は従来の小型通信HUDを維持し、その直上だけに遅延警告を追加する。

## 遅延警告

RTTスパイクと設定の補正範囲 `(D + R) * 1000 / 60 ms` を比較する。超過1Fは黄色、超過2F以上は赤色とする。どちらの場合も `INCREASE D OR RB LIMIT` は黄色で表示する。

単発スパイクを見落とさないよう最悪値を8秒保持する。保持中でもDまたはRを増やして同じスパイクを覆えた時点で警告を解除する。通常RTTの到着で保持期限を延長しない。

## コントローラ設定処理の確認と補強

既存処理は、F4で途中終了した割当を空欄で上書きせず保存し、設定画面を開いただけで以前のデバイス割当を消さない。今回、この挙動を維持した上で次を追加する。

- 設定画面内にも「キャラクター決定前に完了」「左右で担当割当」「Enter/ボタンで割当開始」「F4で保存して閉じる」を常時表示する。
- 相手側の遷移などで設定画面を開いたままキャラクター選択を離れた場合も、途中割当を保存して自動的に閉じる。次画面へ入力遮断状態を持ち越さない。

## 確認範囲

固定幅表示、案内文、黄／赤境界、8秒保持、通常値による期限延長防止、設定増加による即時解除を単体試験対象とする。実ゲームでは疑似遅延を加えた2窓で同期状態を比較する。F4の物理コントローラ手操作と別解像度の配置は別途確認事項とする。

32bit Releaseビルドと28 CTestに成功。110〜140ms・損失5%の同一PC 2窓を40秒実行し、双方1216確定F、`REC / FRAME / STATE / MEM`の差分・欠落0、失敗0。ホスト397回、クライアント391回のロールバックが発生し、最大深度は双方4。WASAPI activeを維持した。ログは`build_logs/character_select_guidance_20260912`。自動入力試験のため、物理コントローラでF4を開閉する手操作と最終画面配置の目視は未確認。
