# Fightcade／サードストライクから学ぶ対戦ユーティリティ

調査日: 2026-09-11。対象: MBAACC Ver.1.07 Rev.1.4.0／CCCaster_v10。

後続作業でHUD・実測値・確定スコア・学習表示を実装した。[現行実装と検証](2026-09-11_utilities_implementation.md)を参照。本書以下の「現行」「未実装」は調査時点の記録。採用した通信窓は1秒、RTTは最新サンプルであり、下記2秒中央値案から変更している。

今回は公式ヘルプの画面、公開コード、3rd用トレーニングスクリプトを照合し、MBAACC向けの表示仕様・実装順序へ落とした。**調査・設計まで完了。新しいゲームHUD・勝敗集計・観戦・トレーニング機能は未実装。** Fightcadeの実対戦・現行配布バイナリの動作確認はしていない。公開ソースの動作を、現在の全利用者の画面と同一とは扱わない。

## 2. どんな機能が、何を、いつ表示するか

| 機能 | Fightcade側の表示・条件 | MBAACCに生かす内容 |
|---|---|---|
| 相手探し | ゲーム別チャンネル。公式画像では中央チャット、右に募集／利用不可のプレイヤー一覧、名前・国旗・接続バー。相手の右クリックからChallenge | 将来のロビーでは「募集中／接続中／対戦中／離席」を明示。国旗を回線品質の代用にしない |
| 挑戦と準備 | Test gameで単独起動確認→相手へ挑戦→受諾後に両側起動。通知パネルに挑戦・メンション | 現在のTRAINING・コード募集から、事前の起動確認と接続段階の表示を充実。接続済みと対戦開始済みを分ける |
| 対戦者とスコア | 上部に両者名とVS／FTn、条件を満たすとスコア・ランクを追加。名前が空ならその側の名前を描かない | P1/P2の識別と確定スコア。2先が双方合意・実装済みの場合だけ「2先」を表示 |
| 統計切替 | Backspaceでオンライン時は4段階。0=非表示、1=FPSと自分のd/ra、2=Ping/Jitter追加、3=実RBと双方d/raを含む詳細 | 「簡潔／詳細／非表示」。診断を見たいときだけ開ける。キーは既存ゲーム入力・F4との衝突確認後に決定 |
| 回線・処理警告 | 統計行の警告カウンタが100以上で赤。毎更新で減衰。低FPS・ジッタ・RB条件で加算する | 数値と「入力待ち」「処理超過」を併記し原因を分ける。色だけで伝えない。低FPSだけで回線不良と決めない |
| 入力履歴 | 共通HUDはフレーム番号・方向・ボタンと、通常／巻戻し等の色・記号。オンライン当事者では自分側を対象、観戦時は確定側バッファを使う分岐 | 入力変化と継続Fの履歴はMBAACC標準実装（ユーザー確認）。新規機能扱いを撤回。将来の予測／確定入力診断と標準履歴は別に扱う |
| チャット | 下部に最大7行。新着時に期限を延長し、入力中・履歴表示中にも表示。ミュート時は相手へ不達通知 | 将来のロビー／対戦後チャット。戦闘中に操作を奪わない。F4中の遮断・押しっぱなし解除と整合が必要 |
| 観戦 | 観戦人数アイコン。受信人数からサーバー分1を引き、人数が1を超えた場合に表示 | 観戦中継が実装されるまでは人数を作らない。未対応と0人は別 |
| 配信用出力 | プレイヤー名・スコア・キャラ・勝者等を個別テキストに出力。前回と違う文字列だけ保存 | セット集計ができた段階でOBS向け出力。ゲームスレッドで毎Fファイルを書かず、確定イベントを別処理へ渡す |
| リプレイ | 公式にリプレイの入口。3rd支援側には観戦用スクリプトもある | 入力保存・再生・版管理が先。現在無効のゲーム本来のリプレイ保存は有効化しない |
| トレーニング | 3rd専用支援に8録画枠、ランダム／反撃再生、判定、入力履歴、ブロッキング練習 | MBAACCではA/B/C/D入力、ガード後／起き上がり後反撃、シールド練習へ再設計。3rdの判定値は転用しない |

ロビーの接続バーの厳密なms閾値、ランキングの現行サーバー計算、観戦の配信基盤は今回確認していない。説明画像から推測して実装仕様にしない。

## 3. 公開コードで確認した表示ロジック

### 統計は設定値・計測値・未受信を区別する

[vid_overlay.cpp の VidOverlaySetStats](https://github.com/fightcadeorg/fightcade-fbneo/blob/c95950140e2424643a0bb589dc444f0defe03155/src/intf/video/win32/vid_overlay.cpp#L1393) と [run.cppのBackspace処理](https://github.com/fightcadeorg/fightcade-fbneo/blob/c95950140e2424643a0bb589dc444f0defe03155/src/burner/win32/run.cpp#L797) を確認。

- `d`は入力遅延、`ra`はrunahead。**MBAACCのR（ロールバック上限）とraは別物**。
- 表示名は実時間RBだが、実装は前回統計更新からの「巻戻し総Fの増分÷回数の増分」という整数平均。単一の直前イベント深度と同一ではない。巻戻しが発生しないまま600 emulated framesを超えると0へ戻す。
- 相手の設定が未受信なら`d?-ra?`。観戦・無効PingではFPS側へ分岐する。
- Pingは1000ms以上を`+999ms`、Jitterは100ms以上を`+99ms`と短く表示する。
- 警告は更新回数ベースで減衰する。実時間の秒数へ勝手に読み替えない。
- 参照版のジッタ処理には、配列長10に対し添字を`> 10`で戻す箇所と、Ping平均用の和へジッタ配列を加算する箇所がある。静的確認上の問題であり、配布版での再現は未確認。式や閾値の丸写しは避ける。

### スコアは表示コードから独立したゲーム別検出

[GameDetector](https://github.com/fightcadeorg/fightcade-fbneo/blob/c95950140e2424643a0bb589dc444f0defe03155/src/intf/video/win32/vid_overlay.cpp#L299) は開始待ち→勝者待ち→開始待ちの状態機械を持つ。開始から300内部更新を超えて勝者を調べる。描画するかはランク戦／非ランク戦のスコア設定、検出器の有効性、状態で決まる。

3rdの定義はMain RAMの`0x2867a == 99`を開始条件、`0x16cd6`／`0x16cd4`を`gts`勝利検出、`0x11384`／`0x1138b`をキャラ識別に用いる。これはCPS-3エミュレーション内のゲーム別定義で、MBAACCのプロセスアドレスではない。MBAACC側は既存GameMemと対象版の勝敗状態を検証して独自に作る。

### トレーニングはMBAACC標準機能と既存ツールを優先する

訂正: 入力変化ごとの履歴と継続F表示はMBAACC標準にあるため追加実装しない。有利不利表示の実装参照は、ユーザー指定のkosunan/MBAACC_Trainingとfangdreth/MBAACC-Extended-Training-Modeへ変更した。[両実装の計測・表示条件](2026-09-11_mbaacc_frame_advantage_reference.md)を参照。以下の3rd調査は比較記録であり、MBAACCの実装仕様ではない。

[input_history.lua](https://github.com/Grouflon/3rd_training_lua/blob/73ec4c062108fd3494c4fae6b81a61f9cf518b81/src/input_history.lua) は方向と6ボタンが変わり、前の記録とフレームも異なる場合に追加。最大15件を保持し、次の変化までの差分Fを継続時間として描く。長押しで画面を埋めない。

[frame_advantage.lua](https://github.com/Grouflon/3rd_training_lua/blob/73ec4c062108fd3494c4fae6b81a61f9cf518b81/src/frame_advantage.lua) は攻撃開始・接触・双方の終了を追跡し、計測中や必要情報がない間は表示を控える。双方終了時刻の差を有利不利とし、正負の符号と色を付ける。MBAACCではヒットストップ、着地、キャンセル、ムーン差を検証してから対応する。

## 5. MBAACC向け表示仕様案（未実装）

### 普段のHUDと詳細表示

- 簡潔: `RTT 42ms | D 2F | RB上限 4F | RB実測 1F`。未採取は`—`。値は説明用で実測ログではない。
- RTT: 新規RTTサンプルの中央値を直近2秒で表示する案。最終サンプル時刻・有効件数を持ち、2秒超の未更新は`未更新`とする。描画のたびに同じRTTを新サンプルとして追加しない。
- ジッタ: 新規RTT間の絶対差の平均を直近2秒で表示する案。隣接2標本未満は未計測。採取方式を明記し、片道遅延変動と混同しない。
- RB実測: 直近1秒に開始した巻戻しの最大深度とする案。1回の再計算の各Stepで重複加算しない。採取有効で1秒間イベントがなければ0F。上限とは別ラベル。
- 詳細: 上記の窓定義、RB回数／窓、Present要求間隔と通常更新開始間隔の最新／最小／最大、WORK、WASAPI／QPC切替状態。既存の120サンプルMIN/MAXと新しい時間窓を混同しない。
- 非表示: 統計を隠しても切断・入力待ち・時計故障の重要通知は残す。FPSを瞬間的なフレーム精度の証拠にはしない。

### 状態ごとの表示と優先順位

| 状態 | 表示案 | 表示を終了する条件 |
|---|---|---|
| 準備／募集 | 起動確認、コードをコピー、対戦相手待ち | 接続成功／キャンセル／失敗 |
| キャラセレ | 現在D/R、変更要求中、次の試合から反映、F4案内 | 相手ACKと適用世代の成立／要求取消 |
| 戦闘 | 簡潔HUD。詳細は任意 | 画面遷移／表示設定変更 |
| 入力待ち | 「相手入力を待っています」＋待ち経過時間 | 実際に入力待ちが解消／タイムアウト。通常3秒・起動合流30秒を変えない |
| 時計故障 | 「音声時計を利用できません：QPCで継続」 | セッション内は詳細に残す。健康なWASAPIと同一表示にしない |
| 結果 | セッションスコア、元のVS RESULT MENU、必要なら相手選択待ち | 双方ONCE／片側キャラセレで遷移。保存無効を維持 |
| 切断 | 「相手が終了」「通信応答なし」等、確認できる原因と戻る先 | ランチャーの状態として保持。推測で相手の故意切断・敗北としない |

同時発生時は終了理由→入力待ち／時計故障→設定反映→統計の順で優先。短い入力待ちは毎回点滅させず100ms継続後に表示する案。これらのmsはUX提案で、Fightcadeの仕様や実測値ではない。ゲームスレッドが待機中だとHUDを更新できないため、通知の即時更新にはランチャー側状態供給または待機経路の慎重な設計が必要。

### スコアと配信用出力

`sessionId + matchId + confirmedResult`をキーに、確定した1試合を一度だけ加算する。ラウンド勝利と試合勝利を分離し、再計算・結果画面の再描画・再送では増やさない。引分け・切断は独立状態。ランク反映は双方の報告照合とサーバー裁定が成立してから。

表示はP1/P2を固定し、ホスト＝P1という推測をしない。キャラだけでなくムーンも表示できるようにする。勝者固定・敗者スタイル変更と2先は既存サーバー案に従う。対戦コードによる通常対戦へ勝手に2先終了を課さない。

OBS向けは整合したスナップショットJSONを基本に、必要なら名前・スコアのテキストを併設。確定イベント後にworkerで一時ファイルから置換し、旧セッションの勝者やスコアを残さない。失敗してもゲームを止めず、ランチャーに出力失敗を表示する。

## 6. 実装順序と完了条件

| 順序 | 範囲 | 完了条件 |
|---|---|---|
| 1 | HUDの簡潔／詳細／非表示、未計測・未更新の区別、D/R説明 | 実データの供給元とラベルが一致。小画面・DPI・全画面でゲームHUDと干渉せず、F4／ゲーム入力を維持。表示ON/OFFで必要範囲の処理時間を比較 |
| 2 | 新規通信サンプルによるジッタ、実RB、入力待ち・終了理由 | 合成サンプルで窓・期限・リセットを確認。短い実対戦でログと表示を照合。通常更新と再計算を分ける |
| 3 | 確定試合スコア、OBS出力 | 双方勝利・引分け・切断・再送・巻戻しを含め二重計上ゼロ。原メニューと片側キャラセレ優先を保つ |
| 4 | トレモ有利不利・反撃練習 | 標準入力履歴を維持。有利不利は指定2ツールを参照し、計測中／確定と停止・着地等を実機照合。ネット対戦にはトレモ状態変更を持ち込まない |
| 5 | ロビー、観戦、リプレイ共有 | 認証・接続・中継・版管理・確定入力再生が必要。UIだけで利用可能とは表示しない |

同期・時計・入力・フックへ実装を入れる際は`cccaster-verify`で変更に必要な32bitビルドと短い実対戦を行う。今回の成果物は調査資料・表示案・ロードマップ訂正なので、ゲーム起動／ビルド／配布更新は行っていない。
