# キャラセレをローカル操作と最終選択の交換へ分離する

対象: カニファン版 Ver.1.07 Rev.1.4.0、32bit。Steam側には未適用。

キャラセレにはスナップショットによる予測がなく、従来はD2より遅い相手入力を毎フレーム待っていた。途中のカーソル移動を一致させる必要はないため、専用入力時計・中央バッファを維持したまま、キャラセレだけD0のローカル消費へ変更した。相手のフレーム入力・時計位相・世代バリアはこの画面では待たない。ゲーム状態の書込みはゲームスレッドだけで行う。

## 選択と確定

- 各自が自分のキャラ・ムーン・カラーを操作する。相手のカーソルは確定通知後に自動選択される。途中の一致は要求しない。
- カラー確定後はその選択を固定する。キャラ選択中のB抑止と、カラー確定前の戻る操作、F4設定中の自分の入力遮断は維持。
- 所有者が確定した実キャラと実カラーを送る。ランダムの再抽選は相手で行わない。受信側は実キャラのセルへ解決し、従来spectateと同じselector設定＋GameMemの通常入力経路で自動選択する。
- ステージはホストが操作し、最終値を交換する。受信確認までは遷移判定だけ保留し、背景・描画・入力時計は進む。ステージからキャラセレへ戻す操作は閉じる。
- 世代、改訂番号、受信確認を毎回再送する。古い世代・古い改訂は受け付けず、確認済み改訂も後退させない。両キャラとステージの確定がそろってからロードへ進み、戦闘入口の既存RNG／世代合流を実施する。
- D/R操作はホストが適用順を決め、確定値を公開。クライアント要求は番号付き再送と確認を使う。自分のキャラ確定後の新規設定要求は取り消し、次戦入口で反映する設定を固定する。

通信版10のSYNC_TICKへ60byteの選択情報を追加し、ヘッダー予約byte7を拡張版1とした。旧DLLとの混在は明示的に拒否するため、両側を更新する。戦闘入力形式、D+R<=8、既定D2/R4、再送・予測上限・再戦の合意条件は維持。独立選択を使わないFakeGameの入力履歴経路は残した。

## 逆アセンブルの根拠

対象EXEの既存逆アセンブル `I:/work_space/CCCaster_Steam/build_logs/steam_analysis/legacy.asm` を参照（Steam命令の転用ではなく、カニファンEXEの解析結果）。

- `0x4281B7..0x4281C1`: カラー確定でプレイヤー確定印とselector mode=4。続く処理でmode=5へ進む。
- `0x4284E0`: 両selectorがmode=5かを判定。
- `0x427256..0x427272`: ステージ処理の戻り値255でロード側へ遷移。`0x42725B`の5byteを照合してフックし、この戻り値だけを合意状態で制御する。
- `0x4289B0..`: selectorの実キャラ・カラー・ムーンを対戦用データへコピー。確定直前のCOMMITと、対戦入口のLOADEDを両方照合した。
- `0x488760`: ステージ番号は0〜99の探索範囲。受信値の範囲も制限。
