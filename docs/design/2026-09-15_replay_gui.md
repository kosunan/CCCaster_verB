# リプレイ自動保存とGUI観戦

## 仕様

- 再戦画面にはCCCasterのHUDを表示しない。キャラ選択・対戦・ネット観戦の名前／勝数／D/R配置は維持する。
- 対戦参加者は訂正済みの結果確定時、各自のゲームフォルダー `ReplayVS` に標準 `.rep` を一度だけ保存する。ネット観戦者による録画は今回の対象外。
- ファイル名は `YYYYMMDD_HHMMSS_mmm_P1-名前[WIN]_P2-名前.rep`。2P勝利なら2P名の後ろに `[WIN]`、確定できない結果は末尾 `[UNDECIDED]`。Windows禁止文字を置換し、同名は連番で保護する。
- ゲーム本来の保存関数で全ラウンド・入力・RNGをシリアライズする。日時は標準ヘッダーにも記録。全構造と長さを検査してから公開し、失敗時はログと `.part` を残す。既存ファイルは上書きしない。
- GUIの「リプレイ観戦」→「リプレイ観戦を開始」でゲーム標準のREPLAY SELECTIONへ進む。CLIは `--replay`。通信接続は不要。
- 一覧でF4から既存のコントローラ設定を開き、方向入力・A決定・B戻るを使用する。一覧でのホットプラグ再検出を有効にする。再生中にトレーニングの保存／復元操作やネット対戦HUDは適用しない。

## 旧版から参照した実装

`I:/work_space/CCCaster/OLD/targets/DllAsmHacks.hpp` の `saveReplay` と `forceGotoReplay`、`OLD/netplay/ReplayCreator.hpp` の標準REP構造を照合した。対象はMBAACC Ver.1.07 Rev.1.4.0のみ。

- 保存関数は `0x446C90`、stdcallの引数は標準リプレイオブジェクトと保存名。戻り値だけでは書込み成功を判断できないためファイルを検証する。
- 起動分岐は `0x42B475` から `0x42B541`。命令・遷移先を照合し、一覧到達後に元の分岐を復元する。従来Replay定義に残っていたTrainingへの誤った短距離分岐を使用しない。
- ロールバックで標準入力の記録位置だけを復元していたため、RNG記録に予測フレーム分が重複した。各ラウンドのRNGベクタ末尾も復元し、再計算で上書きするよう修正した。

## 検証

根拠は `test/logs/auto_replay_20260915/` と `test/logs/replay_gui_20260915/`。

- Release 32bitビルド・39 CTest・Python74件成功。
- 遅延15〜25ms／5%損失の65秒実対戦では1,433確定Fについて入力・代表状態・記録MEM項目に差分／欠落0。結果待機中の自動保存は各側1回。
- RNG記録の修正前は両側で余分な記録数に差が生じた。修正後の2ラウンドの戦闘領域SHA-256は両側で一致した。`inspect_native_replay.py`で各入力列とRNG列の範囲・件数も検証する。
- GUI日本語／英語ページ、GUIから標準一覧への到達、日時／両者名／勝者マークのファイル表示、F4設定の保存と再読込、通常DirectInput経路の仮想DS4のA入力によるロード→再生画面を確認。
- 自動化ツールの短いキーボード押下は決定に届かなかったため、再生開始は通常設定経由のDS4で確認した。物理機器の手操作は未確認。
- 保存試験は既存の短縮試合設定を使用している。試合時間・体力を変更しない記録の全編再生一致、全キャラ・特殊状況は未確認。途中までの標準対戦試験は終了操作により結果保存前に終了した。

最終版の55秒実対戦（date_pair）でも1,433確定F差分／欠落0、両側の戦闘データ一致、各1回保存と標準ヘッダーの日時を確認。テスト用に変更した入力設定を復元し、試験前の208 INIのハッシュ一致を確認。CLI／GUI／DLLは32bit PEとSHA-256を照合してtest/runtime/MBAACC_1〜3へ反映した。
