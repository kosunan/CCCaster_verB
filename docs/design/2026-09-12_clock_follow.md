# ホスト時計の固定推定と小数周期による追従

## 実装した挙動

ホストのWASAPI時計を基準にし、クライアントだけが追従する。音声への無音供給・起動位置0の拒否・QPC故障切替・入力の独立採取・ゲームスレッドの状態操作は従来どおり。

- 通信のNTP時刻、入力締切、世代開始合意を `1tick = 1/60µs` に統一した。60Hzの1Fは正確に1,000,000ticks。診断表示と旧互換API以外で整数µsへ丸めない。
- 周期補正は1tickの百万分率を蓄積し、絶対締切を作る最後にだけtickへ丸める。小さな速度差を毎F切り捨てない。TimeScaleによる余りも保持する。
- `PeerClockModel` は重ならない16秒窓で、各秒の最小RTT標本から窓内最小RTT+500µs以内を選ぶ。4標本以上・3秒以上の幅を必要とし、回帰残差と傾きの推定誤差を検査する。隣接2窓の位相と傾きが一致したときだけ採用する。大量の同時刻パケットだけでは採用しない。
- 採用後はアフィンモデル（時刻差と速度差）を固定する。新しい標本は検証に使い、正常な標本への毎回の再フィットは行わない。持続的変化は2窓で再確認する。検証できない場合は最大48秒で失効し、再学習する。
- 速度差は±250ppm以内。採用速度差から正確な逆数で周期へ換算し、適用速度を1Fあたり最大1tick分ずつ変化させる。
- 位相補正の目標は `誤差/600`（60Hzで時定数10秒）、上限は±15ticks/F = ±0.25µs/F。1Fごとの補正量変化も最大1tick/F。小さい誤差は小さい補正となり、反転時・推定失効時も段差を避ける。新しい観測で公開済みの締切を動かさず、採取後の次の締切に一度だけ適用する。
- 1F以上の大差復帰は同方向の別々の2観測でのみ行い、`REPHASE` に記録する。微差の位相追従とは別の経路。最大100ms、残差250µsという従来の復帰上限を維持する。
- 時計源世代を送信し、WASAPI→QPC時には採用モデルと相手予定を破棄する。切替前のエコー・遅延した旧世代パケットから時計を再学習しない。入力の冗長受信は継続する。

通信版は10のまま、拡張識別を5から6へ更新した。時刻単位が変わるため、**双方へ同じ新DLLを適用する必要がある**。旧拡張との接続は拒否する。

## 分解能と推定の限界

1/60µsは既存WASAPI時計の内部表現単位であり、音声機器や待機の実精度ではない。`IAudioClock::GetFrequency` による位置の換算と、相関QPCによる補間は既存実装を使用する。このPCではQPCが10MHz（100ns）、診断の音声位置周波数は352,800Hzだった。音声位置の周波数とAPI更新周期・精度は同一ではない。小数補正の蓄積はこの表現で利用できる端数を捨てないためのもの。

回帰の判定幅は観測ノイズからの採用基準であり、100%の正しさを意味しない。固定の片道遅延差、持続的な経路変更と時計差の区別、温度ドリフト、別PCの異なる音声デバイスは残る。低品質な通信では学習に長時間かかる、または採用できない。その間は nominal 60Hz を維持し、確証のない微差補正を行わない。真の速度差がある別PCで全Fをローカルの厳密60Hzにも一致させることはできない。

参考: [Microsoft GetPosition](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition)、[GetFrequency](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getfrequency)、[NTPの時刻・遅延推定](https://www.rfc-editor.org/rfc/rfc5905.html#section-8)。

## 描画OFFの切り分け

`CCCASTER_CLOCK_FOLLOW_TRACE=1` で、設定締切・位相補正・速度補正・推定採用状態を `ClockFollow` に記録する。同じフラグで通常進行の追いつきを `InputCatchup`、戦闘／キャラセレ中の描画省略を `RenderSkip` に記録する。`Rollback BEGIN/END` 区間内の省略を再計算へ帰属できる。通常進行の追いつき条件そのものは変更していない。

120秒、同一PC2窓、D2/R4、疑似受信遅延15〜25ms・損失5%、自動入力、WASAPI active、追加計測ONで確認した。

| 項目 | ホスト | クライアント |
| --- | ---: | ---: |
| ロールバック回数 | 25 | 33 |
| 再計算中の描画OFF | 30F | 36F |
| 通常入力の追いつきによる描画OFF | 0F | 0F |
| その他の戦闘／キャラセレ描画OFF | 0F | 0F |
| 大差復帰 REPHASE | 0 | 0 |
| 記録した設定周期の最小〜最大 | 16666.666667µs | 16666.416667〜16666.666667µs |

双方の採用は約60秒後。クライアントの採用モデルに対する位相差は同一戦闘世代3の3,259Fで−533.483333µsから−8.55µsへ収束した。設定締切・推定差の値であり、相手機器に対する絶対的な実誤差の測定ではない。

5,737確定FでREC/FRAME/STATE/MEM差分・欠落0。今回の描画OFFはすべてロールバック中の中間画像省略であり、微差の高速追いつきは再現しなかった。起動・ロードを含む全画面の描画省略数や、ユーザーが見た場面そのものを特定した値ではない。

根拠: `build_logs/clock_follow_20260912/normal_16s/` の `game_1.log`、`game_2.log`、`clock_follow_analysis.json`、`rollback_comparison.json`。この診断後、時計源切替時の旧エコー排除・入力時刻の範囲検査と診断項目の整理を追加した。通常時の時計モデル・位相制御は同じ。

実QPCによる通常更新の間隔は両側5,166区間で最大絶対誤差310.233333µs／3759.833333µs、±3µs超過10／25件だった。設定周期の改善を実更新の全F保証に読み替えない。追加計測のある診断結果で、従来の計測OFF試験とは直接比較しない。
