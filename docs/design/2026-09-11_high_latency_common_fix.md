# カニファン版へ高遅延対策を適用

2026-09-11、単独作業。MBAACC Ver.1.07 Rev.1.4.0、32bit。Steam版で検証した共通アルゴリズム3点を、カニファン版の現行コードへ個別に適用した。Steam固有アドレス・署名・保存表・通信識別子は導入していない。

## 変更

1. ロールバック上限で最古の未確定入力が到着したら1枠を空けて再開する。最新まで全入力を待つ余分な停止を除去。待機判定では履歴を変更せず、その後のReconcileで不一致を検出・復元する。R0や予測禁止場面は必要な全確定入力を待つ。
2. 最新入力を消費ACK待ちにせず送信し、未消費先頭の10入力も別パケットで再送する。通常送信・受信通知後送信・keepaliveで共通処理を使用。同じ窓なら1パケットのみで、古い欠落入力の回復を維持する。
3. DLLのCCCASTER_TEST_NETWORKによる模擬遅延・損失を受信側1回にする。両端の送信と受信で二重に加算しない。

D2/R4、通信版10、独立入力時計、60Hz絶対締切、ゲームスレッド上の保存復元、カニファン版固有の起動素材キャッシュ等は維持する。

## 検証

- 32bit Releaseビルド成功、22 CTest成功。消費ACKの遅れと最新送信、最古1件の到着での再開、不一致保持、R4上限、R0の回帰項目を追加した。
- 実機45秒、同一PCの2窓、自動入力、D2/R4、片道60〜96ms・損失5%。両側WASAPI稼働。ログ: `build_logs/bounded_real_20260911_135334`。
- REC/FRAME/STATE/MEMの1918確定フレームが一致、差分・欠落・失敗0。ロールバック562/534回、最大4F。絶対WTとメニューカウンターは既存比較器の除外対象。
- 戦闘開始後120Fを除いた実提示要求間隔の中央値16.667/16.667ms、99%点19.507/19.349ms、最大23.265/33.334ms。20ms超8/8標本。標本数1263/1262。通常更新＋描画の中央値0.384/0.384ms。再計算の全対戦最大18.518/7.010ms。
- 修正前のカニファン版との同条件比較は今回は実施していないため、改善率は主張しない。全フレーム16.667ms以内、全キャラ・長時間・手操作の網羅は未達。
- 集計: `src/harness/analyze_lag_pacing.py`、`build_logs/high_latency_port_20260911/pacing.json`。PACE/FRAME_TIMINGの診断付き測定であり、設定周期・平均FPSだけを瞬間値として扱わない。

`build/bin/libcccaster_hook.dll` と `_TEST_MBAACC/MBAACC_1/cccaster`、`MBAACC_2/cccaster` のDLLのSHA256一致を確認。値は `094A627A1F3F90D47D3C915C405894990ECB0901E834D99852B3B539E63C2380`。CLIも同じビルドから反映した。

変更前の対象ソースを `build_logs/high_latency_port_20260911/*.before` に保全。テスト前後の27 INIファイルに変更なし。既存のゲームプロセスは試験前に存在せず、試験で起動した対象だけを終了した。既存未コミット変更は保全し、コミットは作成していない。
