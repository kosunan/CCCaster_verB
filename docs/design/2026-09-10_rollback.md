# ロールバック接続の設計

確定入力待機を基礎に、対戦中だけ最大Rフレームの予測を許し、Dは入力遅延として分離する。ネットワークからゲームメモリを復元しない。ゲームスレッドが連続確定位置を走査し、最古の予測不一致へ戻り、保存した32bit入力を使ってPresent間のゲーム本体で再計算する。再計算中は新入力採取・消費ACK・通常速度待機を行わない。上限や画面境界では確定を期限付きで待つ。

保存範囲は旧res/rollback.binのMD5と構造を検証して展開した61ルート・3061ノード・1241047Bを基準とする。親の復元後に子ポインターを解決する。指定外の隙間を保存する従来の64Bマージは用いない。リングには入力適用前の状態と浮動小数点環境を保持する。ゲーム版専用の範囲であり、成功判定には実ゲームでの再計算一致が必要。

段階：保存器と予測履歴の単体検証、確定入力の強制巻戻しによる実ゲーム検証、遅延・欠落で実際の予測不一致を起こす対戦・再戦検証。音声の重複とリプレイ履歴は副作用として別途検査する。従来の待機ビルドは退避して保持する。

## 実装で確定した条件

- 通信版4。Dは入力遅延、Rは予測上限として分離し、両者とも非負・D+R<=8を必須とする。通常入力はPresentの冒頭で1回だけ採取して中央のMatchInputBufferへ公開する。通信スレッドは定期tickの合間も受信と新しいwriteHeadを約1ms間隔で確認し、次の16ms周期を待たず送信する。
- 相手入力は直前の適用値を維持して予測する。確定値の連続区間をゲームスレッドが照合し、最古の不一致へ戻す。予測上限に達した場合は、さらに1フレーム進める前に訂正を処理する。再計算中は新入力を採取しない。保存した32bitの自入力と中央バッファの相手確定入力を使う。
- Present転送とImGui描画を止め、通常のメトロノーム待機を通らずゲーム本体を進める。ゲーム本体の描画処理自体は実行されるが、再計算の途中画像は画面に転送しない。禁止されているCC_SKIP_FRAMES_ADDRは書き換えない。
- 戦闘開始前とKO・時間切れ後は予測しない。双方のNO_INPUTフラグを人形キャラクターの切替も含めて判定する。ラウンドや画面境界では未確定入力を解消し、相手の消費ACKを確認してから世代を切り替える。
- 旧保存表のSHA256は271CA9D750F48E56CCF2F242B3EA73D48A5582B6536ADBB223D31579726899B0。末尾MD5一致と総サイズ1241047Bを検査してGameSnapshotLayoutへ展開した。
- 旧表は別のフック位置向けで、Present境界に必要な共有ヒットストップ(0x557D2A)、タイマー(0x563574/0x562A70/0x55DEC0)、速度補間(0x55DEF0/0x55DF24)が不足していた。ゲームの0x423B0D〜0x423B52、0x472A20の処理を根拠に19Bを追加。これを戻さないとKOスローの長さが変わり乱数が分岐する。
- 戦闘の予測が可能なフレームだけ保存する。イントロや再戦開始直後はゲーム内リプレイが構築途中のため保存対象にしない。再計算時は浮動小数点環境とリプレイ入力の圧縮履歴カーソルも復元する。再確保された配列は現在の割当先を使う。
- 効果音の再生箇所0x4DE210で元命令を照合してフックし、同じ巻戻し区間で既に鳴った効果音を抑制する。新しい効果音は再計算時に許可する。既に鳴った音を時間を遡って取り消す機能ではない。
- 比較器は各フレームの最後の再計算結果を採用し、双方で確定した区間の入力・相対進行・位置・体力・乱数を比較する。重複ログは再計算の証拠として数え、途中の番号欠落は許容しない。絶対WorldTimerとmenuCtrは別集計する。

ランチャーもEXEと同じフォルダーのcccaster_v10.iniを読み、D/Rを8bitに変換する前に範囲を検査する。DLLと設定の参照先を一致させるための変更。
