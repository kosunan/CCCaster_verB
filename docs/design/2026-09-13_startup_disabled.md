# 起動時の高速化を一時停止する

後続のユーザー指定で、コミュニティEXEへの対応と全体SHA-256検証を加え、起動高速化を再有効化した。[現在の実装・検証](2026-09-13_community_exe.md)。以下は一時停止した時点の記録。

2026-09-13。ユーザーから「一旦起動時の高速化を解く」「ファイル圧縮の環境依存があるかもしれない」と指定され、起動高速化を共通方針で停止した。

## 変更範囲

- `StartupTrace.hpp` の起動方針を高速化OFFに固定。環境変数の追加設定なしでCLI／GUIの通常起動にも適用する。
- 起動用DDSの圧縮ブロック直接転送と旧テクスチャキャッシュを無効化し、元のD3DX素材読込へ戻す。素材ファイル・既存キャッシュを削除／変換しない。
- 起動中はゲーム時計1倍、Sleep省略OFF、描画あり。キャラ選択に到達したゲームスレッドで、既存の入力・60Hz待機・ロールバック用設定へ引き継ぐ。起動後の再計算の高速化は維持する。
- DxDiag情報収集の省略、ダミーD3Dデバイス生成の回避、コントローラ列挙の先行実行、暗転短縮、起動演出状態の直接スキップも停止する。
- 指定モードへの自動メニュー操作・モード指定の分岐は維持する。DLL準備完了イベントは高速化と分離し、ゲーム入口を準備完了前に解放しない。
- 対応版のEXE判定とDLL側のコード照合、通信版10／拡張6、入力・同期の条件は維持する。前作業の詳しい起動失敗診断も収録する。

## 確認済み

- 32bit Releaseビルド成功、関連8 CTest成功。配布候補3バイナリのPE Machineは0x014c。
- GUI worker経由のトレーニング起動は `target=1 mode=20 kind=4112 versus=0` が一致。キャラ選択のPresent・通常入力経路をログで確認し、2秒維持。今回1回の入力受付到達は8.416279秒。物理画面・手操作の確認、平均値や他環境での起動時間の保証ではない。
- 起動時に `acceleration=off gameClock=1 sleepBypass=0 originalAssets=1`、素材差替え無効、キャラ選択後の既存タイミングへの移行をログで確認。
- 最初にモード指定の分岐まで外した試行は、メニューから別画面（mode=100）へ入り30秒で未完了。分岐を維持した最終版の成功結果と分けて保存した。
- 40秒の2窓対戦（15〜25ms、5%損失）は双方SYNC OK、938確定Fの入力・フレーム・代表状態・保存領域の差分／欠落0、双方RB発生。比較器の最低1000Fに届かず終了1だったため、時間を延ばして再確認した。判定基準は下げていない。
- 最終50秒・同条件の2窓対戦は1527確定FでREC／FRAME／STATE／MEMの差分・欠落0、比較器成功。ホスト3回／クライアント8回のRBを確認。両コピーのCLI／DLLは最終ビルドと一致。既存24 INIと2ゲームEXEの26ファイルは追加・変更なし。既存GUIは停止・上書きしていない。

根拠: `build_logs/startup_disabled_20260913/`。`build.log`、`build_final.log`、`ctest.log`、`training/result.json`（未完了）、`training_final/result.json`（成功）、`pair/rollback_comparison.json`（最低F不足）、`pair_final/`、`preserved_before.json`、`preserved_after.json`、`package.json`。
