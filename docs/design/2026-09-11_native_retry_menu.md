# 再戦をゲーム本来のメニューと確定項目通知へ変更する

対象: MBAACC Ver.1.07 Rev.1.4.0、32bit。Steam版は別管理。

## 実装

- 再戦用ImGuiパネルの描画呼出しを外し、ゲームのVS RESULT MENUを使用する。入力時計と中央バッファを維持し、再戦中はD0で自分の入力だけを通常のGameMem経路へ渡す。相手のカーソル操作や毎フレーム入力は送らない。
- `0x4299CB` の既存フックでゲームが移動した後のカーソルを読み、ゲームの決定結果を記録する。ロード／キャラセレへの遷移は両者の合意とACKまで保留する。決定後のカーソルを固定し、保存・終了の項目は選択不可にする。自動リプレイ保存無効、入口30Fと押しっぱなしの遮断、移動直後の決定抑止を維持する。
- 元ゲームの項目確定はCONFIRMビットを使うため、Aボタンを通常のGameMem入力経路でメニュー決定へ変換する。派生入力メモリへの直接書込みは行わない。
- `RetrySelection` は世代・確定項目・相手確定項目のACKを持つ。未選択、ONCE、キャラセレを区別する。双方ONCEで再戦、片側キャラセレでキャラセレへ進む。確定済み項目の変更、古い世代、遅延した未選択通知による巻戻しを拒否する。
- 確定した自分の選択は相手のACKまで待つ。片側キャラセレを受信した未選択側は選択を要求されず、ACKを公開して遷移できる。次画面でも直前の選択とACKを保持・再送し、遷移直前のパケット損失で相手を取り残さない。
- 相手が旧戦闘に残っている間は、その末尾入力の再送を続ける。再戦到達後は入力送信を止める。次の戦闘では既存の世代・RNG・未来開始時刻合流を使う。
- 通信版10・拡張3。拡張2以前のDLLとは混在不可。両者の更新が必要。

## 検証方法

22 CTestで、双方ONCE、片側キャラセレ、ACK待ち、古い世代・再送・逆順・不正値拒否、次画面でのACK保持、旧戦闘末尾再送と再戦入力非送信、旧DLL拒否を確認する。

実機の `CCCASTER_TEST_NATIVE_RETRY=1` は `CCCASTER_SCRIPT_INPUT=1` 時だけ有効。元ゲームでは最初の決定がメニューを開く操作となるため、開く→移動→決定の入力列を使う。`CCCASTER_TEST_REMATCH=0` は双方ONCE、1/2は指定側だけキャラセレ、3はメニューを開いた後約40秒待って双方ONCE。

`CCCASTER_TEST_RETRY_QUICK=1` は試験専用。各戦闘世代の600F以降に残り時間を1、P1/P2体力を11400/5000にしてゲーム本来の時間切れと勝敗遷移を通す。通常進行と再計算の同じフレームへ適用する。時間制限・勝敗を短縮した疎通試験であり、通常ラウンド長の実対戦とは区別する。

`verify_native_retry_pair.py` は元メニューの確定観測、送信値、双方の遷移先、ACK、確定後入力の遮断、ローカルF/WTの連続性を検査する。戦闘は `compare_rollback_pair.py` の確定フレームだけを比較する。

## 確認範囲

- 初期試験 `build_logs/bounded_real_20260911_160805`：通常ラウンド長、60〜96ms・損失5%、160秒。5747確定F一致、再戦入口まで到達。旧試験の一度だけのA入力ではメニューを開くだけで、確定・遷移は未達。
- `build_logs/bounded_real_20260911_161121`：短縮試験、40秒待機。Computer Useで元の再戦メニューと追加パネル非表示、Alt+Enterによる全画面切替後のメニュー表示を確認。A入力の確定経路を追加調査したため、この試行では再戦遷移未達。
- `build_logs/bounded_real_20260911_161418`：短縮試験、65秒、60〜96ms・損失5%。試験入力でA+CONFIRMを渡し、双方ONCE→ロード→戦闘入口を確認。先に選択したホストは244ローカルF、約4秒相手を待機。両側のローカルF/WTの欠番なし、確定後入力0、双方のACKを確認。以後はAのみの通常入力にも同じ変換を適用する。
- `build_logs/bounded_real_20260911_161555`：Aのみの試験入力を本番用ゲートで変換。短縮80秒、同ラグ、クライアントだけが実メニューの項目1を確定。ホストは全期間未選択のままACKを返し、両側がキャラセレ→ロード→戦闘へ復帰。2237確定FのREC/FRAME/STATE/MEM差分・欠落・失敗0、うち復帰後800F。選択通知・遷移・ローカルF/WT連続性の比較も合格。
- **最終版** `build_logs/bounded_real_20260911_161733`：短縮110秒、同ラグ、D2/R4。元メニューを開いて約40秒待機後、双方AでONCE確定。ホストをAlt+Enterで全画面へ切替し、`_App.ini` のWindowed=0、元メニュー表示、全画面のまま再戦後の戦闘表示をComputer Useで確認。ホストは2413F、クライアントは2461Fで確定し、ACK後に双方Loading→InGameへ復帰。再戦中2465/2470FのローカルF/WT連続、確定後入力0。2155確定F一致（再戦後718F）、差分・欠落・失敗0。`native_retry_comparison.json` と `rollback_result.json` が根拠。

全画面切替で変化したテストコピーの `_App.ini` は、作業前SHA256と一致するもう片側のファイルから復元した。実コントローラ、別PC、各画面解像度の総合確認は別条件。

最終DLLを両テストコピーへ反映し、ビルド出力とSHA256一致を確認した。SHA256は `59A28B669E6A425C12234900ACC4545C308F262D6ECC34E4A315C48872914A86`。CLI/DLLともPE Machine=0x014c。テストルート55 INIは作業前と一致。結果は最終ログの `final_files.json`。今回起動したゲーム／CLIだけを終了し、既存GUIと未コミット変更を保全した。
