# 観戦HUDと連続ドロー後の同期停止

## 変更

- 観戦の初期表示を対戦と共通の左右プレイヤー名・中央勝数に変更。F1でフレームバー／ADVへ切り替え、再押下で通常表示へ戻る。トレーニングの初期ONは維持。
- 観戦の下端は対戦HUDと同じ色・文字サイズ・中央配置で `D 2F  R 4F` のように表示。値は観戦開始情報のホスト側SelectionStateから取得し、観戦端末のローカル設定は使わない。再戦画面でも観戦用の名前・勝数とD/Rだけを表示。
- 決着後の音声終了待ちを同期フレーム基準に変更。通常戦闘中から音源の開始フレームを記録し、イントロまたは双方の操作終了後だけゲームスクリプトの音声終了判定を置換する。実音声を早送り・巻き戻ししない。通常戦闘中の音声終了判定は元APIを使用する。

## 旧版と原因

参照した旧版は `I:/work_space/CCCaster/OLD/targets/DllMain.cpp`。`checkRoundOver()` は人形交代を考慮して双方のNoInputを調べ、R+5フレーム後に `Skippable` へ移る。`RoundStart` 通知で戦闘に復帰し、RNGを再同期する。現行は決着演出も同じ入力世代で同期し、次ラウンドのintro=2で世代を切り替えるため、演出時間の端末差を許容できない。

報告時のローカルログを `test/logs/spectator_hud_draw_report/reported_1～3.log` に保全。ホストがbase=262144へ進んだ一方、相手はframe=202259の旧世代入力待ちで3秒後に終了していた。

修正前の無操作試験 `test/logs/spectator_20260914_224416/` でも2回目のドロー後に再現。frame=197833でround_countが1対2となり、ホストがframe=197840の入力待ちで終了。入力・代表状態はそれまで一致していた。操作ありの短縮ドロー試験 `spectator_20260914_224129/` では再現せず、決着演出を無操作で進める条件が必要だった。

ゲームの0x46A89B/0x46A8B9は音声終了API 0x4DE1E0を呼び、その結果でスクリプトの進行を待つ。従来のフックはintro=1/2だけを対象としており、決着演出では実音声時間へ戻っていた。修正後は2回目の決着音源657もframe=197569で両側同時に終了する。

## 検証

- Release 32bitビルド、38 CTest成功。ログ: `test/logs/spectator_hud_draw_report/build_final.log`、`ctest_final.log`。
- 無操作・時間切れドロー3回→再戦→次試合、3窓95秒、15～25ms／5%損失: `test/logs/spectator_20260914_224631/`。対戦・観戦とも3,825確定Fの入力／代表状態／記録MEM／観戦INTROに差分・欠落0。205 INI不変。中立入力のため訂正ロールバックは0回で、対戦比較には `--allow-no-rollback` を指定した。
- Computer Useで観戦の名前・0-0・下部D2F/R4F、F1でフレームバー表示、再押下で名前・勝数へ復帰することを確認。2回目のDRAW画面も確認。
- 最終DLLの通常攻撃入力・勝敗確定・再戦、3窓70秒、15～25ms／5%損失: `test/logs/spectator_20260914_224851/`。ホスト8回／相手10回ロールバック、対戦・観戦とも2,020確定F差分・欠落0。2-0での試合終了をセッション勝数1-0として記録し、観戦へ反映、次試合へ進行。205 INI不変。
- 最終DLLはPE Machine 0x014c。MBAACC_1～3のDLLがビルド元とSHA-256一致。再戦画面専用のHUD経路はビルド・実ゲーム進行で確認し、同画面の目視は未実施。

再現用には既存の試験入力と併せて `CCCASTER_TEST_ROUND_DRAW=1` で戦闘世代600F以降に双方同体力の時間切れを作り、`CCCASTER_TEST_DRAW_IDLE=1` で戦闘入力を中立にする。`CCCASTER_TEST_RANDOM_STAGE=1` でキャラセレを決定入力だけにする。これらは自動試験専用で通常プレイでは無効。

全キャラ・特殊な音声停止／ループ・別PC／実回線の長時間は未確認。観戦ログ末尾の切断は試験終了時の対戦プロセス終了に伴うもの。
