# 再戦入口のACK待ち合いを解消する

## 報告と確認できた原因

双方未選択でタイムアウトするとの報告。保存した本線ログは実験側 `build_logs/rematch_reported_20260911/game_1.log` と `game_2.log`。
ホストは再戦世代1245184のepoch barrier、クライアントは旧世代のprevious epoch drainで停止。
クライアントは最終入力1181816まで進み、ホストはそれより1F早く画面を切り替えた。
相手が旧世代をもう消費しないのに、その消費ACKが増えることを要求したのが待ち合いの原因。
表示されたSync Timeoutは無操作制限の証拠ではない。

## 修正範囲

再戦画面へ入る際に限り、通常の消費ACKに加え「相手が直後の同一再戦世代へ到達済み」という既存通知を旧履歴の待機終了条件にする。
既存の入口は自身の未確定ロールバック履歴を解決してから世代を公開するため、到達通知は相手が旧世代の入力消費を終了した証明になる。
古い世代、別画面、世代の飛び越しは認めない。消費ACKの値や実際のゲームフレームを書き換えず、予測入力を確定扱いにしない。
旧履歴は従来どおり境界まで残す。通常入力の3秒制限、合流の30秒制限、切断検知を維持する。
両者ONCE・片側キャラセレ優先・リプレイ保存無効・遷移確定後の高速化は維持。

この変更は終了演出の長さが端末間で違う理由そのものを直すものではない。対戦状態の不一致をこの判定で解決済みと見なさない。

## 検証

- 修正前の実ゲーム `bounded_real_20260911_040416`：遅延15〜25ms・損失5%、双方無操作で再戦選択を約35秒保持。無操作自体で必ず切れるわけではなかった。
- `rematch_boundary_20260911`：実装済みSceneRunnerを使う2プロセスharness。ラウンド長を1761/1762Fにし、旧ACK133196に対しクライアント終端133197の待ち合い条件を作る。PEER CLOSEDログを経て双方196608の再戦世代に到達し、正常終了0。
- input_gateに直後の同一画面・古い通知・別画面・飛び越し・消費番号不変の検査を追加。16単体テスト成功。

テスト用 `CCCASTER_TEST_REMATCH=3` は双方40秒無操作、その後P1が2400F、P2が2460FでONCE。4は継続無操作。いずれもSCRIPT_INPUT=1時のみ。
harnessの `--round-frames` で終了演出の長さの差をモデル化できる。実ゲームの戦闘が一致した証明の代用にはしない。

修正前の長い再戦待機では、262560以降に再戦画面内の乱数差を検出（入力・FRAMEは8074F一致、STATE/MEMは1119F差）。戦闘中の比較差はない。メニュー内乱数の非決定性をこの修正で解決済みとは扱わない。次の戦闘開始では既存のホスト乱数同期を行う。
