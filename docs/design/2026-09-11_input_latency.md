# 入力経路の調査と表示遅延の短縮（2026-09-11）

対象: I:\work_space\CCCaster_v10。指定された I:\work\_space\CCCaster\_v10 ではなく、これまで作業している実在パスを使用した。
通信版10。双方のEXE/DLLを更新する。D/Rの設定値・コントローラ設定は変更しない。

## 調査した入力経路

1. DirectInputHook::Pollが実コントローラを採取し、割り当てに従ってGameInputへ変換。
2. InputTimelineがWASAPIメトロノームの締切で入力を採取。F4遮断、画面別制約を適用し、フレーム付き中央バッファへ公開する。
3. 通信はバッファの入力を再送。ゲームはDフレーム前のローカル入力と相手の同フレーム入力を取り出す。相手が未達ならRの範囲内で予測し、不一致を巻き戻す。
4. ゲームスレッドのRealGameMemory::WriteInputで、*[0x76E6AC]を起点とするP1方向+0x18/ボタン+0x24、P2方向+0x2C/ボタン+0x38へ書く。キャラセレの未選択B遮断もこの境界で行う。
5. ゲーム内部の入力バッファ処理を経由し、0x46B720は入力オブジェクト+0x468+プレイヤー番号*0x2Cから方向を取得する。0x46B660はボタンを変換し、前回Holdとの比較からPush/Hold/Releaseを作る。
6. 0x46D7A0付近で各キャラクターの入力処理。0x46D8B8から0x46B720を呼び、0x46D8CBからEの複合処理0x46D6D0を呼ぶ。向き等の補正後、0x46D908でキャラオブジェクト+0x2E7へ方向を格納する。その後コマンド履歴等の処理が続く。
7. ゲームの更新・描画後にPresentで画像を提示する。

上記5〜6は対象MBAA.exeの逆アセンブルで確認した。内部の全分岐、全キャラクターの技成立条件を網羅的に解析したという意味ではない。入力変換とキャラクター行動の間にはヒットストップ・行動状態・コマンド成立条件も存在する。

## InputInjector.hppが危険な理由

- 方向はテンキー表現。旧OR方式は左下が4|2=6、右上が6|8=14となり、正しい1/9にならない。
- キャラクター内部の+0x2E8からは32bitのボタン状態として処理される。0x46B660ではHoldを0x1000<<ボタン番号、Pushを1<<ボタン番号として生成する。旧ファイルが指定した0x55541Dの下位4bitは、通常のA〜D Push格納位置と一致しない。
- 0x55541Bは変換後の方向で、0x46D908が上書きする。そこだけ書き換えても元の方向・向き補正・履歴とは一致しない。
- Eは方向とキャラクター側の状態に応じたゲーム内部処理を通る。旧コードの早期returnは他ボタンとの同時入力も捨てていた。
- 物理入力の前回値からPushを作る方式は、ロールバックで再実行するゲームフレームの前回値と一致しない。
- 固定P1アドレスだけを操作しても、相手側・他キャラクター・中央バッファとは同期しない。

元ファイルは .ai_workspace/before_input_latency/InputInjector.hpp に保存。直書き関数は=deleteで呼び出しをコンパイル時に禁止し、代わりに通常のGameInputへ変換する副作用のない例を残した。このファイルは従来から実ゲーム本体には未接続であり、置換した変換例も本体の入力取得を差し替えるものではない。安全な低遅延化は既存の中央バッファ経由で行った。

## 本体の修正

旧順序:
ゲームの更新・描画 → 次フレーム入力待機/状態保存 → HUD合成 → Present

新順序:
ゲームの更新・描画 → HUD合成 → Present → 次フレーム入力待機/状態保存

完成済み画像を次の入力待ちで保持しない。DirectXのコールバックを描画前と描画後に分離しただけで、ゲームの次の更新に戻る前に入力書込み・状態保存を終える。レンダースキップ中も後処理を必ず呼び、内部ロールアップを進める。巻き戻し中の途中画像は既存RenderSkipで抑止する。

ゲームの変換済み入力状態へ直接書き込む新しいフックは追加していない。D=2なら約33.3msの設定上の先送り、採取位相による最大約1F、OS/コントローラ/GPU/ディスプレイ側の遅延は残る。表示前待機を消すことでDの合意を破らず短縮する。

## 確認結果

同じビルドで旧順序と新順序を比較。各40秒、受信遅延15..25ms、損失5%。対戦画面でPresentに入ってから元のPresentを呼ぶまでの時間（us）:

|順序|端|件数|中央値|95%点|最大|
|---|---|---:|---:|---:|---:|
|旧|ホスト|871|16888|24079|86660|
|旧|クライアント|872|16896.5|25012|70295|
|新|ホスト|876|144|179|490|
|新|クライアント|874|144|171|297|

コントローラを押してから液晶発光までの総遅延ではない。Present内部のGPU/表示待機も含まない。ログ出力による負荷を含む短時間試験であり、約16.7msの中央値差を全環境の保証値にしない。

旧ログ: build_logs/bounded_real_20260911_015659。確定1106フレーム比較で不一致0。
新ログ: build_logs/bounded_real_20260911_015818。確定1109フレームのREC/FRAME/STATE/MEM不一致0・欠落0・失敗0。ロールバック214/134回、最大深度4/3。既存比較器は絶対WorldTimerとメニューカウンタを除外する。

Release 32bitビルド成功、13テスト成功。新しい変換例は9方向、反対方向相殺、A/B/C/D/E同時保持を確認。実コントローラの操作から画面までの高速撮影測定、全技・全キャラ・全再戦分岐・全GPUの検証は未実施。不具合ゼロは保証しない。
