# 約10µsの反復変動とCPU移動の対策

2026-09-11。5人のサブエージェントを順次利用。音の波形・出力品質は対象外。

## 別々に確認した原因

1. `bounded_real_20260911_072544`のclient909連続区間中819区間は、予定締切自体が正確に+10µs。PhaseFollowerの意図した補正で、全てを処理遅延と解釈してはいけない。音処理は次のスピン終了まで最低12.679ms余っていた。
2. 新しい軽量PhaseSampleを採った`074454`で、885遷移中theta切替78回、目標の1ms超跳躍57回。`error_next-(error_prev-shift_prev)`と`-Δtheta`の残差は中央値1／p9911／最大11µs。直近30packet最小RTTのサンプル切替が通信ジッターを時計差へ持ち込み、連続10µs補正を誘発していた。
3. ETW `074127`／対戦`074130`：5µs以上のmaxGap1278区間内のCPU移動667回。10～40µsの602切替は全てWrQuantumEnd、うち601回別CPU復帰。OSの実行枠終了時の移動を確認。空白全体を移動処理だけへ帰属した訳ではなく、offCPUとISR/DPC、未帰属時間を分離する。
4. 旧`072544` client f132232は締切後9.0µsのうち統計Observe区間6.2µs。120標本走査とFPS除算が締切後にあった。OS中断を含み得るため6.2µs全体を純粋な計算コストとは断定しない。

## 実装

- オフセット推定：既存8秒binの低RTT群（窓最小+500µs）を既存周波数推定で同じ時刻へ投影し平均。有効4bin・3秒以上で採用、未成熟／失効時は従来へ戻す。通常補正上限10µs/F、ホスト固定、同期・予測規則は変更しない。`CCCASTER_DISABLE_PEER_OFFSET_FILTER`で従来比較。
- ゲームCPU：対応構成のCPU0物理コア除外後、OSが配置した論理CPUを起動時に保持。既存process/thread制約を広げず、準備時の維持と終了時の復元を継続。入力・音声workerやOSのIRQ設定は変更しない。`CCCASTER_DISABLE_GAME_CPU_PIN`で自動固定を解除。`CCCASTER_GAME_CPU_PIN=0..31`は許可範囲内のみ明示指定、無効値は従来範囲。
- 統計：締切後は実採取時刻とF番号の保持だけ。120標本の集計・除算・任意整形ログは次OnPresent冒頭へ移動。同じ採取時刻を使い、再計算・Reset時の重複／持越しを防止。SpinReturnのobserveBegin/Endは以後「標本保持区間」。
- PhaseSample：入力時計では整数を保存するだけ。ゲームの締切待機前にログを整形。SpinProbe有効時のみ出力。thetaは採用した推定値、rttは従来30packetの統計値で、必ずしも同一の単一標本ではない。
- 解析：実間隔誤差を予定締切変化／終了遅れ変化／終了後処理変化／QPCと音声時計の換算変化へ整数ticksで分解。誤差を消して表示せず、補正を含む実測値と残差の両方を残す。

明示CPU2/4は別物理コア（mask 0xC/0x30）。`074606`の5µs以上maxGap553区間でCPU移動0回。ETW欠落0、10µs以上の空白20区間は残り、9区間に割込み重複。監視空白最大53.6/45.3µs、実間隔誤差最大6.033/14.633µs。補正を除いた絶対残差p992.633/2.233、最大6.033/4.633µs。

## 検証範囲

32bit対象DLL/harnessと関連単体をビルド。起動中GUIのEXEがロックされ全体ビルドのGUIリンクは失敗したため、既存GUIを停止せず今回対象へ限定。20 CTestと15 Python解析試験成功。時計試験は片道キュー遅延、±250ppm、初期／失効／経路変化／Reset。統計試験は即時集計と400標本一致。

別PC・全CPU構成・長時間、DPCによる残余、永続経路変更時の推定変化、全フレーム誤差ゼロは未達。自動固定は他OSスレッドからCPUを予約する機能ではなく、同一コア競合の可能性は残る。

`spin_etw_20260911_074903`／対戦`074908`：auto CPU8/14、1436確定F一致。位相目標1ms超跳躍は比較対象をSpinProbeの通常Fへ揃えると56→1回、跳躍p995569→11µs（phase_filter_comparison.json）。ただし初期位相差12.293→4.909msでまだ追従中。途中の準備遅れ22.337msは残し、通常間隔最大22.354msを隠さない。

### 残った別系統の大きな遅れ

client f131809で深度1の再計算が44.540ms。その後4Fの準備余裕が負になり、最大42.739msの終了遅れを記録。末尾600区間に含まれないが、試験全体から除去しない。これは終了直前の10µs監視空白ではない。

前F復帰から次スピン終了までの59.396ms窓（再計算以外も含む）には319回のCSwitch、offCPU合計48.704ms、うち315回WrResourceがある。`long_replay_events.json`へ原本の該当イベントを保存。資源待ちの呼出元は今回のスタックなしETWでは未特定であり、音声API・GPU・ネット待ちのどれかへ断定しない。この大きな外れ値は残件。

初期位相差はepoch barrier/RNG終了後に各側がローカルnowでInputTimeline.Beginする経路に由来し得る。合流前の共通未来締切への変更には開始通知と入力採取の分離が必要なため今回未変更。進行中の一括補正や補正上限低下で実測をよく見せることはしない。
