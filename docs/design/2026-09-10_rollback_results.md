# ロールバック実装・検証結果（2026-09-10）

## 実装した動作

コントローラー入力を通常フレームの冒頭で読み、フレーム番号付きで中央バッファへ登録する。通信スレッドは定期tickの間も約1ms間隔で受信と新入力を確認する。自分と相手の入力は同じフレーム空間に保持し、相手入力が未達なら直前の適用値を維持する。

確定値が予測と違ったときは、そのフレームの状態へ戻り、保存した自入力と相手の確定入力で現在まで再計算する。再計算中は新しい入力を採取せず、画面へのPresent転送と通常のフレーム待機を止める。ゲーム本体の描画処理自体は実行されるが、途中画像は画面に出ない。

Dは入力遅延、Rは予測の上限。既定D=2/R=4。DとRは非負で、合計8以下。設定は対戦開始時に固定する。R上限、KO・時間切れ、画面切替では未確定入力を待つ。待機は通常3秒、接続・合流30秒。F12で終了できる。

保存対象は旧表約1.24MBに、Present境界で必要なヒットストップ・KO演出タイマー19Bとリプレイ入力のカーソルを追加。保存スロットは12個で、浮動小数点環境も復元する。効果音は再計算区間で既に鳴ったものを抑制する。

## 通し試験

- 実ゲーム2窓、150秒。`15,25,5`を送信・受信の両方に適用。片道の追加遅延30〜50ms、理論総欠落率9.75%。
- 対戦終了→再戦→再戦後の戦闘まで到達。
- ロールバックはホスト2,414回、クライアント87回、合計2,501回。最大深度は両側とも4フレーム。
- 共通する8,129確定フレームで、入力・相対進行・体力・位置・乱数ハッシュ・ラウンド数・勝数などの比較対象が一致。途中のフレーム欠番なし。
- 再計算時間の中央値はホスト3.567ms、クライアント2.860ms。最大は8.548ms／6.893ms。このPC・試験条件での測定値で、全環境での保証ではない。
- 効果音の重複抑制はホスト906回、クライアント24回。
- 絶対WorldTimerはロード原点の差により7,893フレーム、既存名menuCtrの内部カウンターは5,986フレームで異なるため、別集計して成功判定から除外した。全メモリ領域の一致を意味しない。
- 証拠：`build_logs/bounded_real_20260910_222812/rollback_comparison.json` と両側のゲームログ。

## 追加の通信劣化試験

65秒、`25,45,10`を送受信の両方に適用。片道50〜90msの追加遅延、理論総欠落率19%。ロールバックは258回／223回、合計481回、最大深度4。2,232確定フレームで比較対象すべて一致し、失敗ログと欠番はなかった。証拠：`build_logs/bounded_real_20260910_223109/rollback_comparison.json`。

## その他の検証

自動テスト9件成功。予測上限0/4/8、順序が前後する到着、700フレームの状態再計算、32bit方向・ボタン入力、保存リングの世代、浮動小数点環境、ポインター先復元などを検査した。

ゲーム側だけの停止試験では3,001,464μsで期限切れとなり、待機中のWorldTimerは353→353で不変。証拠：`build_logs/rollback_timeout/result.json`。

## 再実行手順

プロジェクトルートで、32bit MinGW環境を用意して実行する。

```powershell
cmake --build build -j8
ctest --test-dir build --output-on-failure
./src/harness/run_bounded_real_pair.ps1 -Seconds 150 -Network '15,25,5'
python src/harness/compare_rollback_pair.py build_logs/bounded_real_日時
```

比較器は各番号の最終再計算結果を採用し、双方で確定した区間だけ比較する。終了コード0と`passed: true`を確認する。実機試験には自分のMBAACCを `_TEST_MBAACC/MBAACC_1` と `MBAACC_2` に配置する。ゲーム本体は配布物に含めない。

## 確認できていない範囲

実ゲーム検証は同一PC・スクリプト入力。別PC・実回線・NAT越え、実コントローラーによる人の操作、全キャラクター・全ステージ・長時間対戦、保存したゲーム内リプレイの再生は未検証。音声は抑制処理の記録を確認したが、聴感での確認は行っていない。観戦・オフラインモードは今回の完了判定に含めない。
