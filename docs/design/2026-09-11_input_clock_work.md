# 入力時計とロールバック高速化（当初の作業メモ）

実装と結果は `2026-09-11_input_clock.md` に記録済み。以下は着手時の方針。

ユーザー要望：保存・復元・ロールアップを高速化し、コントローラをゲーム更新ではなくWASAPI基準の入力枠で採取する。サブエージェント禁止。検証は最小限の疎通を優先。

確認：現状のMetronomeはゲーム側WaitForNextTick呼出し依存。alpha1（RTT/2からD+Rを引いた値）とalpha2（時計時差）は実際に周期へ反映されるが、ゲームフレーム差の補正ではない。latestPeerFrameは記録のみ。WasapiClockの失敗時は異なる原点のQPCへ切り替わるため、単調性を保証する必要がある。

実装方針：
- 保存表は初期化時に実行計画へ変換し、保存／復元の分岐をテンプレートで除去する。ポインタの動的な解決と親先行復元は維持し、実測で採用判断する。
- 通信スレッドの約1msポンプから独立したWASAPI入力刻みを駆動。ゲームスレッドの停止・巻き戻し中も採取は続く。ゲームへの適用は採取済みフレームを順番通り使う。
- 入力世代開始は画面境界バリア後、停止は世代境界と再戦の高速遷移開始時。通信入力リング600枠を使い、未消費の上書きは禁止。過去の採取時刻を後から捏造しない。
- サンプラーの位相／ゲートをmutexで保護。DirectInputの読み取り・再列挙を直列化し、UI用エッジのスナップショットはゲーム側で別更新する。設定画面の開閉フラグはatomic。F4遮断は送信前と閉じた後の全解放待ちを維持。
- ゲーム側は自分のframe+Dの採取完了まで待ち、その後保存済みframe入力を適用。ゲームが遅れれば入力を欠落させず追いつく。巻き戻しは既存のゲームフレーム番号を維持する。
- 送信冗長窓は単純な最新10件から、相手が未消費の先頭を含む窓へ変更する。ゲーム停止中も入力枠が進むため必要。
- 相手の実適用フレームをパケットで送る。同じ世代だけ比較し、受信経過時間・RTT/2の範囲推定と緩い速度補正へ。時計の絶対時差をゲーム進行差として扱わない。通信版を更新する。
