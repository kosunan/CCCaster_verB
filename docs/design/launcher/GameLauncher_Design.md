# GameLauncher クラス設計書

## 1. 概要
`GameLauncher` クラスは、対象となるゲームプロセス (`MBAA.exe`) を外部コンソール (CCCasterホスト) からサスペンド状態で起動し、ゲーム側の初期化シーケンスやイントロダクション(ロゴ表示など)をショートカット・自動化（**FastBoot**）するためのモジュールです。

CCCaster がゲームと通信を始める前段階の「ゲームプロセスの立ち上げ」と「メニュー画面への強制操作」のみを専用で担い、完了次第メインフローに制御を返します。

---

## 2. モジュール構成 (src/app/launcher)

* **GameLauncher.hpp**: ヘッダー（インターフェース、ターゲット画面定義、およびパッチに使うメモリアドレスの定数宣言）
* **GameLauncher.cpp**: 実装（サスペンド起動、パッチ適用、待機・入力インジェクションの無限ループ）

### 外部依存
* `cccaster_hook.dll` : サスペンド直後に `CreateRemoteThread` と `LoadLibraryA` を組み合わせて対象プロセスにインジェクトされます。

---

## 3. 業務変数設計（Constants / 内部変数）

### 3.1 メンバー変数 (コンテキスト情報)

| 変数名 | 型 | 役割 |
|---|---|---|
| `_targetMode` | `TargetMode` 列挙体 | FastBootの到達目標。`Training`(トレーニング), `VersusCPU`(対CPU戦), `Versus`(対人戦), `Replay`(リプレイ) のいずれか。 |
| `_pi` | `PROCESS_INFORMATION` | `CreateProcessA` で生成した対象ゲームプロセスおよびメインスレッドのハンドル情報。 |
| `_originalHijack` | `uint8_t[9][3]` | ゲームエンジン側の入力上書き(DI CLEAR系)をつぶすパッチを当てた際、元の命令バイト列をバックアップしておく配列。 |
| `_originalEntryPoint` | `DWORD` | `MBAA.exe` が本来実行開始するエントリポイントのアドレス。 |
| `_originalEntryPointCode` | `WORD` | エントリポイントに対して無限ループ(`0xFEEB`)を書き込む前に退避しておく本来の先頭2バイト。 |

### 3.2 固定メモリアドレス (MBAA.exe内部)

ゲーム内部の特定の変数・関数を操作するための決め打ち(Hardcoded)アドレスです。

| アドレス定数定義 | 16進数 | 役割・用途 |
|---|---|---|
| `ADDR_GAME_MODE` | `0x54EEE8` | **[変数]** 現在の画面(UIシーン)を示す1バイト値。「キャラセレ(20)」「メインメニュー(25)」「タイトル(2)」などを識別する。 |
| `ADDR_GAME_STATE` | `0x74D598` | **[変数]** 内部処理ステータス。「起動ロゴ表示中(1/99)」であることを判定し、「スキップ(101)」を書き込んで強制ショートカットさせる。 |
| `ADDR_INPUT_STRUCT_PTR` | `0x76E6AC` | **[ポインタ]** 現在のフレームの入力情報を管理・集計する構造体へのポインタ。この先の `+0x18`(方向キー) や `+0x24`(ボタン) にビットフラグを直接書き込み、偽の「キー入力(例: ENTER)」を発生させる。 |
| `ADDR_SKIP_FRAMES` | `0x55D25C` | **[変数]** 描画(Visual)をスキップするかどうかのフラグ。1にすると画面描画を省くため起動が非常に速くなる。 |
| `ADDR_SFX_ARRAY` | `0x76E008` | **[メモリ領域]** 発音待ちの効果音(SFX)バッファ。起動からメニュー到達までの間に異常に鳴り響くSEをゼロクリアしてミュートするために使用。 |
| `ADDR_AUTO_ACTIVATE` | `0x40E0C0` | **[関数実行コード]** ウィンドウが非アクティブ化されたかをチェックするエンジン関数の先頭。非アクティブ時でも入力を受け付けるよう11バイトをNOP(`0x90`)で潰すために使用。 |
| `ADDR_KEYBOARD_CONFIG`| `0x54D2C0` | **[変数領域]** 古いキーボードコンフィグ。FastBoot中の一瞬だけ物理キーの干渉を避けるためゼロ化する。 |
| `ADDR_FORCE_GOTO` | `0x42B475` | **[関数実行コード]** メインメニュー(25)からサブメニューへ進む際の強制JMPを仕掛けるアドレス。`TargetMode` の指定に合わせてジャンプ先アドレスへの相対オフセットを動的に書き込む(`VersusCPU`なら `0x5C` など)。 |

## 4. 実行シーケンス (処理フロー)

`BootAndMonitor(exePath)` メソッドが呼び出されたときの流れ。

1. **`LaunchSuspended()`**
   * `CreateProcessA` に `CREATE_SUSPENDED` フラグを渡し、MBAA.exe を一次停止状態で起動。
2. **`ApplyInitialPatches()`**
   * DOS/NTヘッダを直接メモリパースしてエントリポイント(`AddressOfEntryPoint`)を算出し、`_originalEntryPoint` に保存。
   * そのアドレスを `EB FE` (無限ループ) で上書き。
   * `ResumeThread` してゲームプロセスを起動させるが、上記パッチにより最初の一歩目でプロセスは足踏みする。
   * ウィンドウアクティブ判定の全潰し、および高速描画スキップフラグ(`ADDR_SKIP_FRAMES = 1`)などのパッチを適用。
3. **`MonitorBootSequence()`**
   * ① **コアDLL注入:** サスペンド停止しているゲームプロセスに対して、`libcccaster_hook.dll` を `LoadLibraryA` スレッド越しに強制ロードさせる。
   * ② **実行再開:** エントリポイントのオリジナル2バイトを復元し、スレッドを再開(ゲーム本体の起動)。
   * ③ **監視ループ:** 16msごとにプロセスメモリを覗き込み、現在のゲーム画面(`ADDR_GAME_MODE`)を調査。
     * 起動ロゴ(1, 99)のときは内部ステートに 101 を強制書き込みしてスキップ。
     * タイトル・メインメニュー滞在時は `ADDR_INPUT_STRUCT_PTR` 越しにキー入力のビットフラグ(方向キー下、決定ボタンなど)を疑似的に流し込み、「自動でメニューを進める」。
   * ④ 24秒でタイムアウトするか、ターゲット画面であるキャラクターセレクト(`20`)に到達した時点でループを脱出。
    * ④ 24秒でタイムアウトするか、ターゲット画面であるキャラクターセレクト(`20`)に到達した時点でループを脱出。
    * **(注意)** `ADDR_SKIP_FRAMES` を `0` に戻す（等速描画に戻す）処理は、ランチャー内では行わず、インジェクトされたコアDLL (`cccaster_hook.dll`) 側で、キャラクターセレクト画面突入から130フレーム（演出完了目安）経過後に自動的に行われます。
    
以上で FastBoot 処理は終了し、制御は元の CCCaster のメイン関数に戻ります。以降の入力同期やオンライン対戦制御は、インジェクトされた `cccaster_hook.dll` 側で実際のゲーム中通信フックとして行われます。
