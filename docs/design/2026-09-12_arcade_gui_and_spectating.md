# 旧版の機能復元を優先しアーケード調GUIへ整理する

この文書はGUI初案時の記録。観戦通信・再生は後続作業で実装したため、現行仕様は[観戦の実装と検証](2026-09-12_spectator_stream.md)を参照する。

## 方針

表示サイズの追加調整：初期・最小ウィンドウを870×640とする。フォントは17/23/34/48の設定を維持。ナビゲーション幅202px、行高64px、主要ボタン高42px、画面内余白を縮める。ヘッダー画像は従来の縮小・右寄せを維持。長い説明や詳細ログは内容領域のスクロールで扱う。確認記録: build_logs/compact_gui_20260912/。

2026-09-12のユーザー指定で、マッチングサーバー構築とランクマッチは凍結する。Cloudflareの準備・公開は当面不要。ランク／カジュアルの検索画面をGUIから外し、`server/matchmaking/` の試作と過去の合意は再開時の資料として保存する。

目標は旧CCCasterの機能を使いやすく仕上げること。特に観戦は大会用途に必須。今回の変更はGUI初案・凍結の反映・旧版との差分整理であり、観戦通信や旧機能すべてを完成させたものではない。

テストは引き続きCLIと既存harnessを使う。ユーザー向けGUIは英語既定、「日本語 / English」で画面全体を切り替える。接続コード・入力値・実行中セッションは言語変更で失わない。製品名、キー名、ファイル名、診断ログ原文は識別可能な表記を維持する。

## 提供画像を使ったヘッダーへの更新

最新の調整：横幅いっぱいでは顔が隠れたため、ユーザー指定でさらに縮小して右寄せに変更。表示幅はmin(480px,ヘッダー幅の42%)、縦横比維持、右端・上端揃え。見出しのX位置はヘッダー幅の35%へ移動し、人物への重なりを避ける。通常画面で両キャラクターの顔が見えることを確認。32bitビルド: build_logs/header_image_20260912/build_right.log、実画面: gui_right.png。以下の横幅合わせは調整前の記録。

同日の追加指定で、ヘッダー背景を提供された1920×1080 JPEGへ変更。原本をEXEへ同梱し、WICで原寸デコードする。最終指定は等倍ではなく、縦横比を保って横幅をヘッダー幅へ合わせる方式。描画高さはヘッダー幅×1080/1920、上端揃え、高さ112pxより下をクリップする。以前の斜線・走査線は外し、文字と紅色／紫の下端線を維持する。

実装はsrc/gui_launcher/HeaderImage.hppとheader_image.rc.in。MANAGEDテクスチャでD3D9 Reset時も画像を保持し、終了時に解放する。読込失敗時は従来のグラデーションに戻る。32bitビルドと実画面を確認。根拠はbuild_logs/header_image_20260912/。画像の上部だけを使うため顔全体は表示しない。

## GUI初案（画像背景を加える前の記録）

構成の参考は『3rd STRIKE』アーケード版の大胆な文字・明確な選択演出。[参考画面の掲載ページ](https://www.imdb.com/title/tt0430635/mediaviewer/rm2952429569/)。同日の追加指定で、配色はユーザー添付のメルティブラッドの表紙・キャラクター選択画像へ合わせた。画像の紅色、黒から深紫への暗部、青紫の光と白い文字を使用する。ゲーム画像・ロゴ・音源を取り込まず、文字と図形で描画する。

- 紅色から深紫へ変わるヘッダー、紫を含む黒の本文背景、紅色から青紫へつながる区切り線。文字は青白い白、補足は灰紫、情報のアクセントは淡い紫。
- 左に番号付きの大きなモード選択、右に選択モードの説明・必要な入力・開始ボタン。選択中のモードと主要ボタンは紅色に白文字、補助操作は紫。短い移動演出と淡い紫のフォーカス枠を付ける。点滅・カウントダウン・操作を止める演出は使わない。
- モードは **01 VERSUS / 対戦、02 SPECTATE / 観戦、03 TRAINING / トレーニング、04 HOW TO PLAY / 操作ガイド**。観戦を対戦と同じ階層へ置く。
- 対戦は募集とコード参加を切り替え、状態・接続コード・キャンセルを近くに表示。トレーニングはコード不要で開始する。
- 観戦画面は現在利用不可と明記する。未接続の入力欄や開始ボタン、架空の観戦者数・配信中表示を作らない。
- マウスとImGuiのキーボードナビゲーションを使用。ゲーム内F4のコントローラ設定を維持。GUIのゲームパッド操作は今回未実装。
- 配信中のゲーム画面では既存HUDの視認性を優先し、ランチャーの大きな装飾を重ねない。

実装: `src/gui_launcher/main.cpp`。`build/bin/CCCaster_v10_GUI.exe` を起動すると初案を操作できる。ゲーム起動には従来どおりMBAA.exe隣のcccasterフォルダーへの配置が必要。

## 旧版との機能差

参照は `I:/work_space/CCCaster/OLD/` の現物コード。旧版を実行して動作保証した表ではなく、旧コードと現行コードの照合結果。旧版の固定アドレスや通信形式を現行へ直接流用しない。

| 機能 | 旧版の根拠 | 現行と復元方針 |
|---|---|---|
| ネット対戦 | targets/MainUi.cpp のNetplay | コード募集／参加は実装済み。GUI経由の接続から手操作・終了までの総合確認は残る |
| 対戦の観戦 | netplay/SpectatorManager.*、targets/DllSpectatorManager.cpp、DllMain.cpp | **最優先の未実装項目**。現行CLIは起動模擬だけだったため、利用不可の案内へ変更。mode=2の列挙値や学習表示だけでは観戦できない |
| 途中参加・追いつき | DllSpectatorManager.cpp の送信カーソル、DllMain.cpp の早送り操作 | 両者の確定入力と初期条件から再生する経路を復元する |
| ローカル対戦／練習のBroadcast | MainUi.cpp::broadcast / gameMode（Versus、Training） | **大会用途の次の優先項目**。対戦者2台のネット観戦と、1台で行う大会対戦の中継を分けて実装・検証する |
| オフラインVersus / CPU / Tournament | MainUi.cpp::offlineGameMode | GUIのオフライン起動はTrainingのみ。他のモードの起動条件とTournamentの振る舞いを追って復元する。列挙値だけを対応済みにしない |
| トレーニング | MainUi.cpp、README.md のリセット／位置入替操作 | 起動・標準入力履歴・有利不利表示あり。旧版の位置リセットやプレイヤー入替、Trialは別途差分確認 |
| コントローラ設定・各種設定 | MainUi.cpp のControls / Settings | ゲーム内F4とINIを維持。名前・D/R・表示設定をGUIから変更する導線は追加対象 |
| 対戦者名・勝数・配信出力 | MainUi.cpp の表示名／勝数、現行SessionScore / ScoreBroadcast | 現行の確定スコアとPID別TXT/JSON出力を観戦側へ接続。観戦側が勝敗を独立裁定しない |
| リプレイ・結果・更新・Server | MainUi.cpp のメインメニュー、Replay / Trial等 | 現行範囲との差分を継続調査。**リプレイ保存は現行ルールで無効を維持**。旧Serverの存在をランク／マッチング再開の根拠にしない |

旧版のSpectatorManagerは保留接続のタイムアウト、観戦者ごとの送信位置、RNG・再戦選択の送信管理、観戦者への中継先案内を持つ。単に3台目のゲームを起動するだけでは旧仕様の代替にならない。

## 観戦の復元設計（未実装）

最初は外部マッチングサーバーなしの直接接続を目標とする。募集側が観戦用コードを共有し、観戦者は同じGUIから参加する。既存の直接接続で通らない回線の問題は残る。観戦用コードは対戦参加コードと区別し、対戦枠に入り込めないようにする。

1. **再生に必要な記録を確定する。** 対象版、通信拡張、セッションと世代、両者の確定入力、キャラ／スタイル／色、確定ステージ、RNG初期条件、シーン遷移、再戦選択、確定スコアを扱う。現行の独立キャラ選択を観戦者の手入力に依存させない。
2. **プレイヤーとは独立した送信経路を作る。** 観戦者ごとに送信位置・確認応答・上限付きキューを持つ。ゲームスレッドは確定済み記録を渡し、観戦送信の完了を待たない。遅い観戦者への追いつき処理や切断が対戦側の進行を止めない設計にする。
3. **観戦側の再生を実装する。** GameMemの既存経路を使い、ゲーム状態の書込みはゲームスレッド上で行う。観戦者の生入力は対戦へ送らない。通常再生・高速追いつき・停止待ちを区別し、中間Presentだけを省略する。CC_SKIP_FRAMES_ADDRへは書き込まない。
4. **途中参加と世代遷移を扱う。** 初期条件＋入力履歴から追いつく方式を最初の候補とし、必要履歴の上限と超過時の「次の試合から参加」を明示する。プロセス内ポインターを含む現行スナップショットの生コピーを他プロセスへ流さない。キャラセレ復帰、再戦、終了の境界を明示的なイベントにする。
5. **大会向け表示を接続する。** 準備中／追いつき中／観戦中／切断、対戦者名、確定スコア、許可された観戦者数を表示する。遅れは確定フレームと再生フレームから算出し、未取得は未取得とする。接続成功だけで「観戦中」と表示しない。
6. **互換性を分離する。** 現行プレイヤー間の通信版10／拡張4と世代・RNG合流を保全し、観戦用能力と記録形式を別途版管理する。旧版観戦プロトコルと互換であると仮定しない。

ネット対戦観戦が通った後、ローカル大会のBroadcastと複数観戦者を加える。中継の多段化・ロビー・アカウントは最初の成立条件に含めない。

## 観戦の受入条件

- 同一PCの対戦者2台＋観戦者1台で、開始時参加／試合途中参加の両方が同じ確定状態に到達する。観戦者を動かしても対戦入力は変化しない。
- 双方ONCEの再戦、片側キャラセレ、キャラ／スタイル変更後、複数試合を接続維持して観戦できる。
- 追いつき中と通常再生のフレーム・表示を別に記録し、追いつけない場合も現在状態が分かる。
- 複数観戦者・途中退出・切断・遅い受信者を試し、観戦者待ちでプレイヤーが停止しないことを確認する。既存の同期・更新周期の測定と比較する。
- ローカルBroadcastは別ケースとして、1台の対戦者2人と別の観戦端末で確認する。
- 大会用の対戦者名・スコアが確定イベントと一致し、再接続で重複加算しない。
- 最後に別PC・実回線で確認する。同一PC3窓だけで大会運用可能とは判定しない。
