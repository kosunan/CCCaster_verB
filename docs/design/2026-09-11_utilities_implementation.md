# 対戦ユーティリティと学習表示の実装

## 追記: 通常HUDの1行化

参考の対戦表示案を踏襲し、統計バーは`RTT / JITTER / D / RB LIMIT / 1F`の短いラベル、白ラベルとシアン値、青灰色の細枠、左端3pxのシアンアクセントで描画する。対戦・再戦は1行、キャラクター選択だけ2行目へ操作キーまたは同期状態を出す。設定の同期・不採用通知は操作案内と差し替え、QPC切替は統計行へ含めるため2行を超えない。RTT、JITTER、1F、D/Rは右寄せ固定幅とし、数値の繰り上がり・繰り下がり、`--`、`STALE`で後続列を移動させない。幅を超える異常値はRTT 99999ms、JITTER 9999.9ms、1F 9999999usで打ち止め、不正なD/Rは`?F`とする。RTTは最新の受理値、JITTERは直近1秒窓の連続RTT差の平均、D／RB LIMITはその画面で有効な設定値、1FはHUD合成・校正待機後の表示要求間隔である。詳細モードを選んでも通常HUD自体は増行しない（学習表示の説明量は従来どおり）。32bitビルドと28 CTest成功。`build_logs/hud_reference_style_20260912/chara_select.png`の640×480実画面でRTT 38ms、JITTER 4.4ms、D2、RB LIMIT 4、1F 16663usの固定幅、白／シアン配色、細枠、2行内への収まりを確認。検証で起動した2窓だけを終了し、55 INIは不変。

ユーザー指定の5人へ、表示刷新・実測値・確定スコア・学習表示・硬直計測を分担した。同時稼働上限のため3人→2人の順で実行し、親担当が統合と実ゲーム検証を行う。

## 表示と操作

- `Ctrl+F3`で簡潔→詳細→非表示→簡潔。既定は簡潔。キーリピートは無視し、切替に使ったCtrl/F3はキーを離すまでゲーム入力へ混ぜない。F4設定の入力遮断は維持。
- 対戦HUDは体力と下端ゲージを避けて下寄せし、詳細だけ上へ広げる。キャラ選択は上端。描画リストを使い、フォーカス・入力を捕捉しない。
- 再戦画面は詳細モードでも上端のスコア1行に限定し、中央のONCE／CHARACTER SELECTを覆わない。
- 簡潔にはセッション勝数、D、RB LIMIT、実RB MAX/1s、最新RTT。詳細には確定試合数／未裁定、RTT最大／ジッタ、RB回数、PRESENT、STEP／WORK、平均FPSを追加。設定F・実巻戻しF・実時間µsを区別する。
- 未採取は`--`、通信の最終採取から1秒以上は`STALE`。観測できた窓の巻戻しなしは0F。WASAPI故障／起動失敗によるQPC使用はHUD非表示時にも通知する。時計の計算・補正は変更していない。
- トレーニングは通信の設定・数値を表示せず、標準入力履歴と有利不利表示を利用する。

## 実測値

`UtilityMetrics.hpp`は直近1000msの窓。ロールバックは復元成功から再計算を開始した時に1件として深度を記録する。描画や内部再計算1Fごとには加算しない。固定バッファでゲームスレッド上の動的確保を避ける。

通信はNTP計算が受理した新しい生RTTだけを通信スレッドから記録する。ジッタは窓内の隣接RTT差の絶対値の平均であり、サンプル2件未満は未計測。HUDはtry_lockで読むため通信スレッドを待たない。旧60回の描画供給最大RTT／ジッタ0固定を置き換える。パケットロス率は推定表示しない。

## 確定スコアと配信

`SessionScore`は対戦開始世代を保持し、終了画面へ到達した時に一度だけ採用する。予測結果は、境界の全入力到着と訂正再計算を終えてから集計する。訂正再計算自体が終了画面へ到達した場合も、ゲーム更新を挟まず入力到着と訂正の確認へ戻る。

既存のラウンド勝数と必要勝数を読み、一方だけが必要勝数へ到達した試合のみ勝者を確定する。両者到達・不正値等は未裁定に数え、HPや大小比較で推測しない。ラウンド単位では増やさず、切断・キャラ選択で試合が途切れても勝利を作らない。同じ終了画面の反復・再計算では二重加算しない。

DLL横の`broadcast/cccaster-score-<ゲームPID>.txt`はOBSのテキストファイル入力に使える。JSONにはactive・revision・session_id・勝数・未裁定数がある。専用スレッドで変更時だけ一時ファイルから置換し、ゲームスレッドはファイルI/Oをしない。JSONとTXTは個別の原子的置換で、2ファイル同時のトランザクションではない。

起動時は空から開始。終了を検知したランチャーは自分のゲームPIDの出力だけ無効化する。ランチャーごと強制終了した場合はファイルが残り得るため、独自の読み手はPIDの生存も確認する。PID別のため同一PC2窓が互いのスコアを上書きしない。接続が変わればセッション集計はリセットする。

## 学習表示と計測

入力変化と継続FはMBAACC標準機能を利用する。追加履歴を重ねたり標準履歴メモリへ書き込んだりしない。

`FrameAdvantageTracker`はトレーニング／観戦用モード1・2だけで有効。通常のゲーム更新後にread-onlyサンプルを採取し、双方行動不能で計測を開始、片側だけ行動可能なゲーム更新を計数、双方が終了した後でのみP1/P2の符号付きFを確定表示する。双方が再度硬直する連係では先行分をリセットする。計測中は数値を出さず、未測定・計測中・確定0Fを区別する。

表示は基準640×480の中央上部（y=82、幅320）で標準の左右入力履歴を避ける。簡潔／詳細／非表示を共通ショートカットで切り替える。確定値の正符号は先に動けた側。これはガード可能・空中受身可能等を網羅した確定反撃判定ではない。

画面停止・固定P1/P2側freeze・操作キャラ側hitstop／receivedHitstopを除外し、simulationFrameが増えないスロー中は計数しない。同一フレーム重複は無視し、欠測・巻戻し・モード／ラウンド／操作キャラ変更・ロード・非戦闘・無効サンプルは破棄する。予定60HzやPresent回数からFを補間しない。

メモリ読取はCarnival Rev.1.4.0ヘッダと可読画像ページを確認。固定の基点とActorDataの+4差を明示。指定の[kosunan版とETMの比較](2026-09-11_mbaacc_frame_advantage_reference.md)に基づき、ETMより確定時公開に限定する。hitstop追加除外・特殊行動の意味は実機条件ごとに確認が必要。

`CCCASTER_TRAINING_TRACE=1`を起動時だけ指定すると、サンプルと計測状態を`[TrainingAdvantage]`へ記録する。通常起動では採取しない。CLIの`--training`はオフライントレーニングの直接起動に使える。

実機確認中に、オフラインではNetplaySession::Startを通らずメトロノームが未始動のまま、ゲームのSleepだけが抑止される既存不具合を発見した。高速起動を終え最初の通常更新に入る時にStartし、処理込みの絶対締切へ待機するよう修正。オフライン試験にも既存の仮想製品ID指定を使えるようP1読取入口を接続し、設定ファイルは変更していない。

## 検証と残件

32bitビルド・28 CTest・59 Pythonテストと4倍速の同期harnessに合格。通常対戦1605F（15〜25ms／損失5%）、双方ONCE2787F、ホスト側キャラセレ2680F（60〜96ms／損失5%）の確定範囲で入力・代表状態の差分0／欠落0。両再戦ケースのスコアは両側ともrevision=1、P1=1、P2=0、未裁定0で一度だけ加算。全INI不変。根拠: `build_logs/regression_20260911_223010_920502/summary.json`と各`session_score_comparison.json`。この後の変更は再戦HUDを上端1行へ絞る描画調整と準備前／観戦用ラベルの修正のみで、別途最終画面試験を行う。

最終DLLの追加試験: `build_logs/utilities_20260911/final_menu/`。60〜96ms／損失5%、約40秒の再戦待機から双方ONCEで復帰し、1637確定Fで差分0／欠落0、実RB最大4F。両側の配信ファイルでrevision=1・P1=1を確認し`active-<PID>.json/.txt`に保管。片側ゲーム終了後、相手終了を204.4443msで検出、両側JSONがactive=false、TXTが0バイトになることを`closed-<PID>.json/.txt`で確認した。

`menu_visual/`は同一最終DLLの再戦画面目視用。簡潔→詳細に切り替えても上端のP1 1-0 P2のみを表示し、ONCE AGAIN／CHARACTER SELECT等の中央選択肢と重ならないことを確認。最終28 CTestは`final_ctest.log`、EXE／DLL／harnessのPE Machine=0x014cとSHA256は`final_binaries.json`。DLL SHA256は`d2fd96070a6c5702e4a90394ee11097e062c0c80c99f0fd871e323e6a8791fbf`。

トレーニング: `build_logs/training_utility_20260911_222922/result.json`、`game.log`、`timing.json`。仮想DS4→DirectInput→GameMemの通常入力でシオン対シオン・タタリへ接近し5A。151〜156Fは停止、167FでP1の行動不能だけ0、168Fで双方0となり初めてstate=2／P1 +1を出力。簡潔／詳細のP1 +1F・P2 -1Fを640×480ウィンドウの実画面で照合した。INI不変。診断34窓の末尾1区間は16.426〜16.885ms、起動遷移を含む全窓の最小0.832／最大24.624ms。予定周期や平均FPSを毎フレーム完全一定の証明にしていない。

修正前の高速動作を観測した`training_utility_20260911_222815`も保管する。この初回プローブは旧ログを退避せず読んでいたため結果列を最終根拠には使わない。試験スクリプトは起動前にログを移動するよう修正した。

観戦モードの計測・表示の対応は観戦通信の実装を意味しない。現行の観戦接続はスタブのため、オンライン観戦での実表示・接続途中・ストリーム欠落からの復帰は未達。全キャラ／全技／別PC・別解像度・音声機器切断は総合確認していない。native resetで時計が変わらない特殊ケース、投げ・空中行動・パートナー・ガード可能状態の意味は追加照合が必要。
