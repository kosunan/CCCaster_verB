# 共通の未来時刻から開始し、再計算のOS待ちを減らす

2026-09-11。カニファン版MBAACC Ver1.07 Rev1.4.0・32bit。本線のみ、Steam版へ移植していない。今回は単独作業。

## 共通開始

InGame世代の準備・RNG合流後に、EpochStartGateでホスト基準の未来時刻を提案する。通信スレッドは各段階の状態を通常パケットで繰返し送る。

- Ready → ホストOffer → クライアントAccepted → ホストCommit → クライアントCommitted。
- ホストはCommittedを確認して入力時計を開始。クライアントはCommit受信後に開始する。
- 提案の余裕はRTT×6＋200ms、最小500ms・最大2500ms。確定前に残り100msを切る場合は新serialで提案し直す。
- クライアントは受領時の時計変換結果を固定。確定後に時刻を更新しない。確定が遅れた場合はエラー終了し、進行済み入力の番号や時刻をずらさない。
- epoch/serial/stageは単調に受理。同一serialの時刻変更、古い段階への巻戻しを拒否。
- InputTimeline.Beginへ最初の採取予定時刻を渡し、その時刻前は採取しない。初回採取前の位相補正も抑止する。
- 通信版10を維持し、ヘッダ拡張を1→2へ更新。旧DLLとの混在は拒否。キャラセレの独立操作は維持。

通信の時計差推定には非対称遅延の誤差が残る。共通hostUsの合意は、異なるPCの物理時刻が誤差ゼロで一致する証明ではない。確定後の通信断・ACK全喪失では一方がarmedになった後に相手が中止する可能性があり、既存の切断処理で終了する。無限の通信喪失下で同時開始を保証するものではない。

## 再計算とOS待ち

従来TimeHooksはゲーム用の1000倍時計の加算量を専用workerのSleep(1)ごとに更新していた。ゲームが時計を何度読んでもworkerが起きなければ加算が進まず、さらにSleep無効化は実際にはSleep(0)でOSへ実行権を渡していた。

既定方式を、ゲームIATのQPC/GetTickCount/timeGetTimeを読取り時に実QPCから連続投影する方式へ変更。倍率変更時はその瞬間の仮想時刻を引き継ぐ。専用1ms workerは起動せず、Sleep無効化時はそのまま復帰する。WASAPI・独立入力・通信・実時間計測の時計は変更しない。比較用CCCASTER_LEGACY_GAME_TIMERで従来動作へ戻せる。

ゲームの描画・オフスクリーンテクスチャ・攻撃判定は変更していない。通常の絶対60Hz締切、CPU0除外／CPU固定、D2/R4と再計算のPresent省略を維持。

## 軽量計測

SpinProbe有効時、ReplayWorkに復元開始／終了・全再計算終了の絶対QPC、保存／入力準備の数値時間を記録。再計算中のTraceFrameの整形は固定長バッファへ延期し、完了後・次の通常締切待機前に整形する。ReplayWork/旧Rollbackの経過時間はこの整形前で締める。整形負荷は通常更新の準備余裕へ反映され、スピン解析から隠さない。

## 同一PC内のCPU選択競合

双方新timerの143155試験では、両ゲームの自動固定がCPU4へ衝突。client PID25120/TID11124、frame132172の復元込み5809.7µs中4770.8µsがoff-CPU。該当CSwitchは同CPUのhost PID26496/TID24152（同じ優先度18）への切替で、3008＋937＋525.7＋300.1µs。再計算が別ゲームの実行を待つ原因を特定した。根拠は `build_logs/bounded_real_20260911_143155/replay_os_sample.json` と `spin_etw_20260911_143151/events.jsonl`。この試験の1525確定Fは一致したが、処理時間は不合格。

GameCoreLeaseの名前付きmutexで、同一ログオンセッションの更新済みCCCaster同士が異なる物理コアを自動選択する。SMTの相手も同じ利用権として扱い、空きがなければCPU0除外の広い許可へ戻す。明示CPU指定は優先し、OSや他アプリの実行を排除する予約ではない。利用権は終了時に解放。単体試験で別スレッドの競合と解放後の再取得を確認。
