# ソース全体の整理と近代化

再戦の実機疎通を通した後、C++20と32bit MBAACCの互換性を保って整理した。依存ライブラリのバージョン、共有メモリのABI、ゲーム用アドレス表は変更しない。

| 対象 | 変更 |
|---|---|
| 全体 | `.clang-format`と`.editorconfig`を追加。132個のC++ソース・ヘッダーの書式を統一。生成済み保存表と過去の参照用保存表は整形対象から除外 |
| ビルド | CMakeの非推奨FetchContent_PopulateをMakeAvailableへ移行。通信実装をcccaster_transportへまとめ、DLL・CLI・harnessが同じターゲットを使用 |
| 設定・ランチャー | ConfigManagerをConfigに委譲し、INIパーサとロックの重複を除去。D/R既定値・上限・通信版をNetplaySettingsに集約 |
| 通信 | UDPのPimplをunique_ptrへ変更し、コピー・移動を禁止。既存の停止・スレッドjoinの順序を維持。未使用の旧受信リング・再戦通知状態を除去 |
| 画面・ロールバック | ランナー状態をSceneRuntimeへ集約。入力採取、ゲームへの入力、フレーム診断を独立関数化。使われない送信関数引数と画面状態を除去 |
| 旧処理 | 呼出し元のないMatchSceneと、現在の32bit入力に対応しない旧RollbackEngine／StateBuffer／StateRingBufferを撤去 |
| UI | 対戦中の設定変更拒否後に置かれていた到達不能な設定送信を除去。再戦表示は実際の両者選択に接続 |
| ログ | 終了時の通知フラグをatomicへ変更。DLL終了時にロックを待てない場合もフラグ書込みが競合しないようにする |

## 疎通で見つかった修正

キャラセレなど予測を使わない画面で、未着入力を待った後にも予測履歴を照合する経路が残っていた。長い画面滞在で上書きされた古い履歴を不一致と扱うと、保存していない状態への復元を試みてしまう。

予測履歴の記録・照合はスナップショットを有効にした戦闘世代だけに限定する。キャラセレ・再戦では中央バッファの確定入力をそのまま消費し、確定済みフレームをACKする。

## 変更の確認

- 全ターゲットの32bitビルド成功。
- 既存の自動テスト10件成功（0.18秒）。新しい大規模テスト群は追加していない。
- 再戦ゲート実装時に、両者ワンスと片側キャラセレの実機疎通を確認。詳細は`2026-09-10_rematch.md`。
- リファクタリング後は35秒の実ゲーム2窓疎通だけで確認し、長時間試験を繰り返さない。

32bitのフックやゲーム内部のポインタを、形式的に新しいAPIへ置き換える変更は行わない。DirectInput／Direct3D9は対象ゲームが要求する経路として維持する。全キャラクター・物理コントローラ・別PC間の実回線の網羅試験はしていない。

変更前のソースは`.ai_workspace/before_modernization/src`へ保存した。従来の未コミット変更も保持し、自動コミットは行っていない。

最終疎通：`build_logs/bounded_real_20260910_232651`。35秒、送受信各15〜25ms遅延・5%欠落。1,358確定フレームで比較対象の差と欠番0、ロールバック300回、同期失敗0。DLLはpei-i386であることも確認した。再戦の長時間試験はリファクタリング後に繰り返していない。
