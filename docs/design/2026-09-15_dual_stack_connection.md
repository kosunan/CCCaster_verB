# IPv4／IPv6の待受・経路選択

## 実装

- GUIの募集設定に「自動（接続品質で選択）／IPv4優先／IPv6優先」を追加した。既定は自動。GUIの設定だけを `[GUI] ConnectionPreference` に保存し、GUIワーカーの起動引数で渡す。通常CLIはこの設定を読まず自動を使用する。
- 優先指定は方式の強制ではない。優先側が不通なら疎通したもう一方を選ぶ。両方が不通の場合は直接確認の終了後にホールパンチングへ進む。
- 募集側はIPv4とIPv6専用のUDPソケットを同じ設定ポートに作成する。片側の作成失敗でももう片側の確認を続行する。参加側は各方式のOS割当ポートを使う。
- 起動前の候補確認を `DualRouteNegotiator` に分離。IPv4・IPv6・LAN候補を並行確認し、募集側が選択を通知、参加側が同じ経路で応答する。選択ACKが失われた場合は、同じ相手・経路からの後続の起動交渉を確認して移行する。
- 候補ごとに50ms間隔で最大20回の往復確認を行う。募集側は相手を確認してから約2秒で判定する。RTTは単調時計で測り、相手の応答処理待ち時間を差し引く。自動の評価値は `損失率(%)×10 + RTT p90(ms) + RTT p90-p10(ms)`。3標本未満には100ms相当の不確実性ペナルティを付ける。評価差1ms以内はIPv6を優先する。この重みは製品側の方針であり、回線品質の普遍的な基準ではない。
- 選択したソケットを破棄せず起動交渉へ渡す。受信コールバック交換を受信スレッドへ直列化し、同じ受信バッファへの二重要求を防ぐ。ゲームへ渡すIP方式の保持漏れと、DLL内のIPv4固定ソケット生成も修正した。ゲーム中の経路変更は行わない。
- 現行の接続コード形式・6時間期限・ソルト・ゲーム通信版10は変更していない。新しい起動前パケットは固定長・識別子・nonce・コードのトークンを照合する。コードのトークンが違う相手が旧方式へ迂回して接続しないようにする。旧起動交渉しか対応していない相手は従来方式で接続し、品質比較非対応と表示する。従来の直接IP指定／旧方式はコードのトークン照合を持たない。

## ホールパンチングと表示

- 既存のLegacyRelayはIPv4の宛先交換にだけ対応している。募集登録のTCP接続は待受中に維持するが、参加側の接続支援要求・UDPパンチ送信は直接確認に失敗してから開始する。
- IPv4で得られた支援経路を使ってIPv6アドレスと各側のIPv6ポートを交換し、IPv6でも双方から送信する。成立した候補を再測定し、同じ優先設定で選ぶ。ゲームデータのサーバー中継は追加していない。
- **IPv4の支援経路も開かずIPv6宛先を交換できない環境では、IPv6パンチは開始できない。** IPv6専用の接続支援サービスや通信中継は今回導入していない。IPv6のみ利用可能で双方が着信を遮断する環境も、この制約に含まれる。
- GUIはIPv4／IPv6ごとに、相手待ち（未確認）、直接確認中、直接成功／応答なし、パンチ用アドレス交換中、パンチ成功／応答なし、交換不可（未確認）、採用方式、キャンセル、ソケット作成失敗を表示する。相手から得た不成立情報は「相手側の確認」と明記する。
- 相手の参加前に、外部からの到達性を成功扱いしない。外部IP取得成功とUDP疎通成功を区別する。結果は接続コードや説明文より上に置き、起動後・終了後も保持する。
- 参加側は最大約16秒で確認を終了する。無応答の参加者は募集側の候補を約12秒で解放し、待受を継続する。GUIキャンセルでソケットを解放する。

- 32bit Releaseビルド、39 CTest、Python解析テスト74件に成功。

- 既存207件のINIをSHA-256で比較し変更0。検証で起動したプロセスだけ終了した。
- 最終CLI／GUI／DLLはPE Machine 0x014cを確認し、テスト用MBAACC_1〜3の通常cccaster_Bへ9ファイルを反映、SHA-256一致を確認した。

## 未確認・制限

- 実ゲーム・GUI試験は同一PC。別PC／実回線でのNAT・IPv6ファイアウォール突破、長時間、非対称な経路、複数参加者の同時競合は未確認。
- パンチ試験はローカルの旧互換接続支援サーバーと直接確認の強制失敗を使った。実際の家庭用ルーターのフィルタリング突破を確認した扱いにはしない。
- 約2秒の有限標本なので低率の損失・長周期の混雑は捉えきれない。開始後に回線状態が変化しても自動切替しない。
- 両方式を通す接続支援／通信中継サービスは未導入。どんなネットワークでも接続できる保証はない。
- 観戦は従来のTCP到達性が必要。今回のUDP品質選択・ホールパンチングを観戦TCPへ流用していない。
