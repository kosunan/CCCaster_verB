# 自動回帰チェック

更新: 2026-09-12。対象版の機能追加を長期に続けるための入口。各試験の合格は[ロードマップ](ROADMAP.md)のP0完成や安定版認定を意味しない。

## 実行

本リポジトリで、32bitビルドが構成済みのWindowsから実行する。ビルド・CTest・Python判定器の故障注入試験・2プロセス同期harnessを毎回実行する。

```powershell
# 編集ごとの高速チェック（harnessは4倍速、ゲーム本体を起動しない）
python -X utf8 src/harness/run_regression.py --profile quick

# 通常戦闘＋高遅延ヒット＋ゲージ交互切替／固定0%（実ゲーム2窓）
python -X utf8 src/harness/run_regression.py --profile real

# 上記＋双方ONCE／ホストだけ・クライアントだけキャラセレ
python -X utf8 src/harness/run_regression.py --profile full

# 失敗したケースだけ再実行。結果に選択範囲を明記する
python -X utf8 src/harness/run_regression.py --profile full --case retry_0

# ゲージだけ（タイマー・双方の体力を固定、45秒×2ケース）
python -X utf8 src/harness/run_regression.py --profile real --case gauge --case gauge_control

# 継続反復。周期未達は選択試行の採取後に失敗。ビルド・同期等の異常は即時中断
python -X utf8 src/harness/run_regression.py --profile full --repeat 10

# 同じ機器・同じ条件の成功結果を指定し、再計算p99が1.5倍を超えたら失敗
python -X utf8 src/harness/run_regression.py --profile real --baseline build_logs/<成功した実行>/summary.json
```

`build_logs/regression_日時/summary.json`に成否、所要時間、HEAD、未コミット内容を含むソースSHA256、EXE/DLL/harnessのSHA256、実行コマンド・ログパスを保存する。外部送信はしない。途中失敗でも結果を保存し終了コード1。`passed=true`のときだけ合格。未構成・依存不足・ゲーム未配置・既存対象ゲーム起動中は失敗し、成功扱いや黙ったスキップにしない。

実ゲームは`_TEST_MBAACC/MBAACC_1`と`MBAACC_2`のみ。既存ゲームが起動中なら既存脚本が拒否する。現在のビルドをテストコピーへ配置し、前のバイナリ・ログを退避する。実行前後のINI一覧とSHA256一致を確認する。子プロセスに渡すCCCASTER環境変数を初期化し、親プロセスの設定は変更しない。試験で起動した対象の終了とログ回収は既存PowerShell脚本のfinallyが担当する。

`.github/workflows/regression.yml`はpush/PR/手動実行時にLinuxのビルド・CTest・Python試験を行う。ワークフローを追加した段階で、GitHub上の実行・必須チェック設定は未確認。ゲームデータやドライバをCIへ持ち込まない。Windows時計・実DirectInput・実ゲームメモリはLinux CIの合格範囲に含めない。

## 通常更新の最大誤差

既定profileはreal。引数なし実行でも周期未達を落とす。明示的なquickは従来の高速チェック専用で、summaryのcadence_checked=falseを確認する。実ゲームの全ケースにUpdateCadenceを追加。InGame/IntroState=0の連続通常更新について、実QPCの最大絶対誤差<=3µs（正確な60Hz、両側600区間以上）を必須とする。平均やp99だけでは合格しない。初回ロールバック以前や未確定Fも含める。欠落・差分矛盾も失敗する。各ケースのupdate_cadence.jsonに超過フレームと付随診断区間を保存する。artifacts/に使用バイナリを保全し、--spike-statesではsources.zipも保存して後からレイアウト・命令列を照合できるようにする。現状はこの条件に届かず、同期比較が一致しても終了1になる。quickは実機周期を確認しない。

```powershell
# 既存12スロットを出力する診断試験。通常性能の測定とは分ける
python -X utf8 src/harness/run_regression.py --profile real --case stress --spike-states --spin-probe
# 既存採取の再解析（未達・証拠不備は終了1）
python -X utf8 src/harness/analyze_update_cadence.py build_logs/<run>/stress_0
```

`--spike-states`は確定済み再計算・予測不可フレームの保存を追加し、Present後に直接書き出す。書出し所要時間は次周期へ影響し得る。R=0の状態証拠は未対応（不完全として失敗）。`--spin-probe`は関数内訳も測る追加診断。`--inline-deadline-trace`はWAIT整形だけ旧位置で行う比較用で、SpinProbeとの併用を拒否する。全状態の対象・形式、閾値の根拠と実測は[設計記録](design/2026-09-12_update_cadence.md)を参照。

## チェック内容

| 層 | 自動判定 | 条件・制約 |
|---|---|---|
| 高速 | 32bit PE、ビルド、CTest、Pythonテスト、harness入力／状態一致 | 4倍速は同期ロジックだけ。実ゲームの瞬間時間評価には使用しない |
| 通常戦闘 | 1000以上の確定F、REC/FRAME/STATE/MEM差分・欠落0、巻戻し発生、WASAPI active、fallbackなし | 45秒、疑似遅延15〜25ms・損失5%、チートなし |
| 負荷戦闘 | 上記＋CombatStress mode2の実適用 | 45秒、60〜96ms・5%。近距離・体力補充・再ヒット。通常勝敗の試験とは分ける |
| ゲージ交互／対照 | 双方0↔300%の到達、上下各3回以上、通常600標本以上、体力・タイマー固定、切替前後4Fの提示周期誤差1ms以内、確定状態一致 | 各45秒、通信劣化なし。対照は0%固定。診断デバッガ／RenderProbeは性能判定時無効 |
| 再戦3ケース | 上記＋確定通知／ACK／遷移／確定後入力遮断／選択結果・ランダムステージ／復帰後120確定F以上 | 各85秒、60〜96ms・5%。戦闘600F後の時間切れ短縮。選択検査用PACE_TRACE有効 |
| 性能比較 | 再計算p99の基準比超過 | `--baseline`指定時。同一機器・条件を人が選ぶ。OS負荷で不合格ならログを調べる |

通常試験の乱数・通信損失は完全な固定seed再現ではない。ソース・バイナリ・入力ログと条件は残るが、同じネットワーク配送順を100%再生する機構は未実装。`repeat`はシナリオの反復数であり1000試合保証の集計ではない。

比較器は同じフレームの最終再計算を採用し、双方が確定した範囲だけ照合する。世代片側欠落、両ログ共通の穴、列数不正、ログ落ち、失敗行も検出。不一致はフレーム・フィールド名・host/client値を最大8件ずつ記録する。未確定の末尾は比較対象外、未確定のまま停止した可能性は短い試験の到達条件で別途扱う。無遅延試験だけは`--allow-no-rollback`を明示できる。最小フレーム数を勝手に下げて失敗を消さない。

`MEM.absolute_WT`と`MEM.menu_counter`の除外は従来仕様を継承。全保存領域を比較しているわけではなく、現状のメモリ取りこぼし検出能力には限界がある。

## チートによる短縮のルールと次の投資

既存の`CCCASTER_TEST_RETRY_QUICK`は600Fから残り時間・体力を変え、元ゲームの時間切れ・勝敗・メニュー遷移を通す。`CCCASTER_COMBAT_STRESS=2`は近距離固定・体力補充・再ヒット上限拡大で攻撃・効果音・再計算負荷を増やす。対象ゲームの版／命令列照合、試験の明示有効化を維持し、双方の通常計算と再計算に同じ操作を適用する。入力は既存GameMem経路を使用し、派生入力やCC_SKIP_FRAMES_ADDRへ書かない。

- [x] 通常戦闘を必ず残し、負荷チート・時間短縮を別シナリオとして集計する。
- [x] 比較器にRNG差、両側欠落、片側世代欠落、破損、ログ落ちを注入して不合格を確認する。
- [ ] 保存→進行→復元→同一入力再進行を実ゲーム内で自動照合する。まず戦闘開始後の短い固定区間で、入力・RNG・代表状態の復元往復を検証する。
- [ ] 保存表とは独立した監視範囲を作る。既存保存表だけをハッシュしても表にない状態は見つからない。版確認済みの書込み可能領域・動的領域を候補とし、候補差分を収集する。描画・音・ポインタ・OS資源を無差別に復元しない。
- [ ] キャラ／ムーン／ステージ／技／設置物／投げ／KO／時間切れをシナリオとして宣言し、到達した状態をアサートする。試験用のゲージ補充・位置・体力設定はフレーム番号付きコマンドに統一し、保存・再計算で二重適用を防ぐ。選択画面・ゲーム本来の状態遷移を飛ばして未初期化を作らない。
- [ ] 未保存候補の特定後、1領域ずつ除外・復元して再現を絞る故障注入を追加する。結果が合格することだけでなく意図した不具合を検出できることを採用条件にする。
- [ ] 長時間保存量対策として、初回差分の前後入力・seed・RNG・保存ブロック・配送順をリングバッファから保存する。現在は全ログを保持し、自動削除しない。
- [ ] 完全な入力リプレイ／通信配送再生／1000試合集計を実装する。リプレイ保存禁止の現行仕様はこの変更では解除しない。

これら未実装項目は「全自動で全デシンクを検出済み」と呼べない理由でもある。今回の一括実行は既知の回帰を繰り返し判定する土台で、全状態の正しさを証明するものではない。

## 実行記録

最終の高速チェックは `build_logs/regression_20260911_172128_253895/summary.json` で合格。32bitビルド・22 CTest・40 Pythonテスト・harness2622F一致まで約16秒（ビルド構成済み・差分ビルドのこのPC）。クリーンビルドや別PCの時間とは区別する。

今回の実行結果は[現行状況](CURRENT_STATE.md)とchangelogに記録する。最初の試行でWindows PowerShellの終了コード取得と、pwsh由来PSModulePath混在の問題を検出し、終了ハンドル保持・子プロセスのモジュールパス指定を追加した。失敗した試行もbuild_logsに保持する。

## 満タン化のスパイク診断

`CCCASTER_GAUGE_STRESS=1`（交互）／`2`（固定0%）は自動入力時だけ有効。双方の体力・赤体力11400、ラウンドタイマー4752をゲームスレッド上で固定する。更新内部でタイマーが4751になった標本は提示前に4752へ戻す。要求30000が満タン演出で消費され0になる値もそのまま採取する。

`analyze_gauge_stress.py <pair> --check` が採取不足・固定不成立・切替窓の提示スパイクを失敗にする。固定0%には `--control` を付ける。ゲーム更新時間と提示間隔は別指標。デバッガを有効にしたログを通常性能の基準に使わない。[逆アセンブル・所有者スレッドの根拠と緩和](design/2026-09-11_gauge_spike.md)。

ゲージ追加後の実行根拠は `build_logs/regression_20260911_181030_136653/summary.json`（ゲージ／対照を選択し完走、118.8秒、22 CTest・49 Pythonテスト）。従来の提示予算1200µsへ戻す対照 `build_logs/gauge_final_20260911/baseline1200` では、1ms超の提示周期誤差を実ゲームで検出し期待どおり不合格にした。これは比較器の故障ではなく、既知のスパイクの検出確認。

## ドライバ内ロックの診断と処理時間の判定

`python -X utf8 src/harness/run_regression.py --profile real --case driver_locks` は、0↔300%・体力／タイマー固定でCS・SRWの長い取得を採取し、同期・フック設置・ログ欠落・INI保全を検査する。診断負荷を含むため、このケースの速度を通常時の性能判定に使わない。既定ケースには追加せず、明示選択時だけ実行する。

`--profile real --case gauge --gauge-max-work-us 1200` は診断なしの更新＋描画時間そのものへ1.2ms上限を課す。提示予算5msで見かけの間隔が整っても超過を検出する。現状は根治未達のため、この厳しい基準は不合格になる。基準を省略した既存の提示間隔判定とは区別する。[観測対象・限界・実験結果](design/2026-09-11_driver_lock_probe.md)。
