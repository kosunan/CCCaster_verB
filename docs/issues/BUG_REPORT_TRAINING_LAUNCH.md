# トレーニング起動前の実行ファイル判定エラー

2026-09-13。報告者はVer.1.07 Rev.1.4.0を使用し、MBAA.exeとcccaster_Bの配置も検証環境と同じとの申告。提供画像では `Unknown / modified executable` に続いて起動拒否され、ゲームプロセス生成前に終了している。

## 現在の対応状況

指定EXEを `Carnival140Community` として対応版へ追加し、ユーザー指定で起動高速化を再有効化した。起動時にファイル全体のSHA-256を照合・表示し、不一致ならゲーム生成前に拒否する。DLL側の.text／.new00照合と各フックの署名検査も実施する。指定された元のMBAA.exeは変更していない。

指定EXEの独立コピーでTrainingの入力・描画経路への到達を確認（単発2.835秒）。同一PCの40秒対戦、15〜25ms／5%損失、短縮コード参加で、新EXE同士1,295確定F、新旧EXE混在1,234確定Fが差分／欠落0。37 CTest、実ファイルを含む633検査、7種類の起動前拒否も成功した。

更新版は通常テスト1・2と独立CommunityRegressionへ反映し、差し替えZIPを作成した。報告者PC・別回線・物理コントローラー・実画面目視は今回未確認。[実装・差分監査・根拠ログ](../design/2026-09-13_community_exe.md)。

## 初期調査で確認できたこと

- 旧診断はファイル不在・読込失敗・破損・PEヘッダー不一致・コード不一致をすべて同じメッセージへまとめていた。ファイル不在で画像と同じ診断を再現した。ただし報告者の原因がファイル不在だと確認したものではない。
- 起動先はランチャーEXEの親ディレクトリの `MBAA.exe`。表示上の版だけでは許可せず、当初はPE32ヘッダーと `.text` のVirtualSize全体のFNV64を確認していた。現在は全体SHA-256も必須にしている。
- ローカルの検証用カニファン版は識別成功。ファイル全体のSHA-256は `04b5bbd582fd795ea2fd27acb5beb2c4e958c6840b1054cda4cb0b70481d949d`。全体SHA-256の不一致だけで実行コードが異なるとは断定できないため、異なる場合は新しい詳細診断と照合する。
- 報告者のSHA-256は `6d1415ca9573100e86a779ac2f81e9bedd322664e3daeae0229a67d13720310a`。後から指定された `E:/06_game/04_メルブラ/MBAA.exe` と一致した。ユーザーによるとコミュニティの主流EXE。
- 読取比較で `.text` は481バイト／173区間の差、FNV64は検証用 `67dfc81b81c56fe1` に対し指定EXE `8094b5405e07e85c`。SizeOfImageは0x3b4000→0x3b5000、4096バイトの `.new00` セクションを追加。`.data` とリソースにも差がある。調査時の `IdentifyHeaders`／`IdentifyFile` はこれを許可せず、今回の拒否が対応判定の未対応に起因することを確認した。この時点では変更内容の意味と固定アドレスとの互換性は未確認だった。後続の差分確認・疎通結果は上記資料を参照。誰がいつ変更したかは未特定。
- 高速化前の `docs/design/2026-09-11_startup_audit.md`、高速化後の `build_logs/startup_first_20260912/audit_final.json`、今回の前後照合で、検証用EXEのSHA-256は同じ `04b5...949d`。高速化実装はプロセスメモリのCALLを書き換えるもので、ゲーム本体ファイルへの書込みではない。
- 指定EXEの比較根拠: `build_logs/community_exe_20260913/comparison.json`。両EXEを起動せず読取のみで解析し、読取前後のバイト列不変を確認。

## 最初に実装した診断修正（対応追加前）

参照した実ファイルパスと拒否理由を表示する。読込失敗を版違いと呼ばず、ヘッダー一致・コード不一致を区別する。解析できた場合はPEの値、実行コードのFNV64、既知版なら期待FNV64を表示する。Steam版にはこのランチャーがカニファン版専用であることを案内する。

対応版の許可条件、DLL側の検査、ゲームの固定アドレス・フック・入力・時計・通信は変更していない。ヘッダーだけ一致したファイルを起動許可に使わない。

## 診断修正時点の検証と残件

- 32bit ReleaseのCLI・GUIと対象テストをビルド成功。CLI／GUIのPE Machineは0x014c。
- `game_build` CTest成功。既知のカニファン／Steam実ファイル、コード改変・欠落、拒否理由を含む595検査が失敗0。
- 隔離したCLIで5ケース（不在、排他ロック、破損、コード1バイト改変、Steam版）を実行し、別々の理由でプロセス生成前に拒否することを確認。元のゲームEXEのSHA-256不変。実ゲームは起動していない。
- 根拠: `build_logs/training_launch_diagnostic_20260913/` の `before_missing.log`、`before_identify.log`、`build.log`、`ctest.log`、`identify.log`、`launch_results.json`。再確認脚本は同フォルダーの `check_launch.ps1`。
- 報告EXEと同じハッシュの実ファイルを読取確認し、拒否の原因は対応判定の未対応と確定した。この時点では指定EXEの差分互換性と実機での起動復旧は未確認で、許可条件は変更していなかった。ユーザー指定の高速化解除版は別途[検証済み](../design/2026-09-13_startup_disabled.md)。素材処理より前のEXE判定で拒否されるため、高速化解除だけではこのEXEを起動できない。

他の起動拒否を調べる際は、起動時の `[GameBuild] SHA-256:` または以下のHash欄を照合する。ファイルを変更しない読取操作。

```powershell
Get-FileHash .\MBAA.exe -Algorithm SHA256
```
