# アプリケーション(Host)とインジェクト(DLL)の責任分界についての設計レビュー (DLL中心アプローチ)

ユーザーからのご提案に基づき、「Host側は起動・通信確立のみを行い、ゲームロジック・同期エンジン・入力処理などの一切合切をDLL側に持たせる（DLL中心アプローチ）」アーキテクチャについて、そのメリット・デメリット、および実現に向けた設計方針を整理しました。

## 1. 提案された境界線（DLL中心アプローチ）

新しい設計では、以下のように役割を明確にスパッと分割します。

*   **Host API (`CCCaster_v10.exe`)**
    *   **役割:** CLI UIの表示、対戦相手とのIP/Portの交換とUDPソケットの確立、そして `MBAA.exe` の起動とDLLのインジェクト。
    *   **特徴:** **ゲームが起動した瞬間に役割を終える（または単なる通信の土管になる）。** これにより、Host側のコードは極めてシンプルになります。
*   **Injected DLL (`cccaster_hook.dll`)**
    *   **役割:**
        *   ゲームの高速起動（FastBoot）
        *   トレーニング画面 / バーサス画面への遷移制御
        *   P1/P2のコントローラ入力の読み取りと加工
        *   キャラセレクトから対戦中、再戦画面に至るまでの**全ロールバック同期エンジンの稼働**
    *   **特徴:** เกมと同じメモリ空間（プロセス）内で完結するため、面倒なIPC（プロセス間通信）の設計やオーバーヘッドを一切排除できます。

## 2. DLLを跨いだ処理（IPC）のオーバーヘッドと管理リスク

もし当初の設計（Hostにエンジン、DLLに入力）のままだと、以下のような問題が発生します。

*   **オーバーヘッド:** 共有メモリや名前付きパイプを毎フレーム（通常60FPS、早送り時は数百FPS）読み書きする際、OSのプロセス切り替え（コンテキストスイッチ）や排他制御（Mutex）ロックの待機時間が発生します。これはミリ秒単位のシビアな格闘ゲームの同期において、致命的な遅延やカクつきを生む原因になります。
*   **管理の複雑化（AI・人間の認知負荷）:** Host側とDLL側で「今ゲームのメモリ状態はどうなっているか？」という**状態の二重管理**が発生します。デバッグ時に「Hostのデータが古いのか、DLLの読み取りがミスっているのか」の切り分けが非常に困難になり、開発速度が著しく低下します。

**結論として、ユーザーのご提案「DLLにすべての同期ロジックを寄せる」ことは、パフォーマンス面でも保守（認知負荷の低減）面でも、圧倒的に理にかなった素晴らしいアプローチです。** 旧CCCasterのような複雑な共有メモリ設計を捨て、モダンな単一プロセスアーキテクチャに生まれ変わらせることができます。

## 3. 次ステップ：実装戦略

この「DLL中心アーキテクチャ」へ移行（リファクタリング）するための具体的なステップは以下の通りです。

1.  **UDPソケットのDLLへの移譲 (またはHostからの直接受け渡し)**
    *   Hostで確立したネットワーク接続（UDPソケットハンドル）をDLLに渡し、通信の送受信もDLL側の隔離されたスレッドで行う仕組みに変更します。
2.  **`RollbackEngine` の引越し**
    *   現在 Host 側にリンクされている `RollbackEngine.cpp` と関連するインクルード（`NetplayState.hpp`, `InputsContainer.hpp` 等）を、CMake 上で `cccaster_hook.dll` 側でコンパイルされるようにビルド設定 (`CMakeLists.txt`) を修正します。
3.  **`GameLauncher` のDLLへの統合**
    *   Host側の `CreateProcess` ループで行っていたスキップ処理を廃止し、DLLインジェクト直後に呼ばれる `GameHooks` の中で、ゲームフレームに介入する形でのFastBoot（画面遷移）処理に書き換えます。
4.  **CLIの簡略化**
    *   `CliMenu.cpp` は、ゲーム起動後にモニタリングやロールバックの処理を行わず、単にプロセスが終了するまで `WaitForSingleObject` で待機するだけのクリーンな状態構造体にします。

このアプローチにより、「ゲームに関する状態はすべてDLLが知っている」「Hostはランチャーに過ぎない」という非常に見通しの良い設計へと進化します。
