# キャラクターセレクト同期機能 業務項目設計書

## 1. 業務の目的
コマンドライン（CLI）からネットワーク対戦を選択したのち、自動的にMBAAのバーサスモード・キャラクター選択画面へ遷移し、両プレイヤー間で入力を同期させる機能を実現する。旧CCCasterの安定した同期パラダイム（ステート管理・インデックスフレーム管理）を踏襲しつつ、v10のモジュール構造に適合させる。

## 2. 前提条件
- `Phase 1` によるCLIおよびステートマシンが実装済みであること。
- `Phase 2` によるUDP冗長化パケット通信が確立し、安定稼働していること。
- `Phase 3` によるメモリフック（実行中のゲームへの値の読み書き）が動作していること。

## 3. 業務項目（実装タスク一覧）

### 3.1 同期ステートおよびインデックス管理基盤の実装
- [ ] **NetplayState の定義**
  - `PreInitial`, `Initial`, `CharaSelect`, `InGame` などのネットワーク状態を一元管理する列挙型を定義する。
- [ ] **IndexedFrame 構造体の実装**
  - 同期ズレを防ぐため、「現在のステートフェーズ（Index）」と「そのフェーズ内での経過フレーム（Frame）」を組み合わせた64bitの複合キー（`IndexedFrame`）を実装する。
  - キャラセレに到達した際、Indexを進めてFrameを0にリセットする機構を作る。
- [ ] **InputsContainer の実装**
  - `IndexedFrame` に紐付く形で、最大数フレーム〜数十フレーム分のパケット入力履歴を保持するキューコンテナを実装する。

### 3.2 画面遷移と描画スキップ制御
- [ ] **ファストブートロジックの拡充**
  - 現在のトレーニングモード直行ロジックを分岐させ、「CLIからネットプレイが選ばれた場合は、メインメニューから『VS Mode』を選択させる」自動遷移マクロを実装する。
- [ ] **描画隠蔽（フレームスキップ）の実装**
  - `NetplayState::Initial` の間は `CC_SKIP_FRAMES_ADDR` 等を活用し、UIアニメーションや遷移画面をレンダリングさせずに裏で最速進行させる。
- [ ] **キャラセレ到達判定**
  - メモリ上のゲームモードが `20 (CharaSelect)` に変化したことをポーリングで検知し、ステートを `NetplayState::CharaSelect` へ切り替え、描画を再開する。

### 3.3 キャラクターセレクト画面固有の入力同期ロジック
- [ ] **入力のフィルタリング（マスク）処理**
  - 旧CCCasterに存在した「決定・キャンセル連打による進行不可バグ」を防ぐため、キャラセレ中専用の入力サニタイズ（`getCharaSelectInput` 相当）を実装する。
- [ ] **ネットワーク越しの入力合成**
  - ローカルプレイヤーの入力に設定されたDelayを付与してバッファへ格納する。
  - 受信した相手レイヤーの入力をバッファから取り出し、P1側とP2側の入力バイト列として結合する。
- [ ] **ゲームメモリへの書き込み**
  - 結合した入力をゲームエンジンの入力バッファ（`0x76E6AC` オフセット等）に直接書き込み、両者の画面でカーソルが遅延なく同期して動くことを確認する。
