# 旧来仕様：キャラクターセレクト同期 業務フロー設計書

## 1. 概要
旧CCCasterにおけるキャラクターセレクト画面のネットワーク同期手法についての業務処理フローを定義します。
新アーキテクチャ（v10）の `core_dll` においても、旧システムの「完全入力同期と入力フィルタリング」を主軸とした仕様を踏襲して実装します。

## 2. 前提条件と課題
キャラクターセレクト画面はゲーム側のメニュー・UIシステムがネットワーク遅延（ラグ）を考慮して作られていないため、わずかなラグで「一方はムーン選択に進んだが、もう一方はキャラ選択のまま」という致命的な状態不整合（Desync）が起きます。
これを防止するために、特定の操作を一時的にソフトウェア的にロックする（入力を握りつぶす）業務フローが必要となります。

## 3. 業務フロー（同期ループ処理）

### 3.1. 状態遷移の検知
- `NetworkSyncLoop`（または `RollbackEngine`）は、毎フレーム `CC_GAME_MODE_ADDR` をポーリングします。
- モードが `CC_GAME_MODE_CHARA_SELECT`（値: 20）に遷移したことを検知すると、キャラクターセレクト同期モードに移行します。
- この時点から、この画面に滞在しているフレーム数（`framesInCharaSelect`）のカウントを開始します。

### 3.2. ローカル入力の取得と抽出
- プレイヤーの入力デバイス（DirectInputやXInput）からローカルの生の入力（`rawInput`）を取得します。

### 3.3. 入力フィルタリング処理（旧仕様の完全踏襲）
取得した `rawInput` を `InputFilter::FilterCharaSelectInput` に渡し、以下のフローで安全な入力値（`filteredInput`）に変換します。

1. **序盤の決定ボタン無効化期間（150F）**
   - 状態：`framesInCharaSelect < 150`
   - 処理：ムーンセレクターの同期ズレを完全に防ぐため、開始後150フレーム間は強制的に `BUTTON_A` および `BUTTON_CONFIRM` の入力ビットを `0` にマスクします。
2. **キャンセル操作の完全封印**
   - 状態：ゲームメモリ上の `P1_SELECTOR_MODE_ADDR` または `P2_SELECTOR_MODE_ADDR`（対象プレイヤーのもの）が `SELECT_CHARA`（値: 0）であるかチェック。
   - 処理：キャラクターを選んでいる最中は、前の画面（メインメニュー）への逆行によるセッション不整合を防ぐため、`BUTTON_B` および `BUTTON_CANCEL` の入力ビットを `0` にマスクします。
3. **カーソル移動直後の決定/キャンセルディレイ（※将来実装予定）**
   - 状態：過去1〜3フレーム以内にA/B/CONFIRM/CANCEL以外の入力（十字キー等）があった場合。
   - 処理：決定・キャンセルを2フレーム間無効化します（UIの描画ラグによるミスクリック・同期ズレ防止）。

### 3.4. ネットワーク送信とロールバック（疑似）実行
- フィルタリング済みの `filteredInput` をUDPパケットで相手プロセスへ送信します。
- 同時に相手からのパケットを受信し、インゲーム中と同様に `AdvanceFrame`（ゲーム関数の実行コール）を呼び出し、両者のゲームメモリを全く同じ入力で進めます。
- **特記事項:** キャラセレ中は状態の保存/巻き戻し（`SaveState`/`LoadState`）は安全に行えないため、ロールバック機能は事実上停止し、純粋なディレイベース（固定遅延）として処理が進行します。

### 3.5. 次の画面への遷移と観戦者対応
- 双方がキャラクターとムーンを決定し、ゲームモードが `CC_GAME_MODE_LOADING` に遷移した時点でキャラセレ同期ループは終了します。
- （※観戦モード実装時のみ）この遷移の直前に `InitialGameState` パケットを生成し、観戦者に確定したキャラクターデータをブロードキャストします。
