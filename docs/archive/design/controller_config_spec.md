# コントローラ設定ファイル・連携仕様書

## 1. 目的と概要
本ドキュメントは、CCCasterの `main_app` (CLI/ホストアプリ)と `core_dll` (MBAA.exeへインジェクトされるDLL) の間で、コントローラーやキーボードのボタン割り当て（バインド）設定をどのように共有し、管理するかの業務仕様とライフサイクルを定義するものです。

## 2. ファイル命名規則・保存先
*   **保存先ディレクトリ**: `cccaster/` フォルダ（実行ファイル `CCCaster_v10.exe` と同じ階層）
*   **ファイル名フォーマット**: `[サニタイズされたデバイス名].ini`
    *   例: `Keyboard.ini` (キーボードの場合)
    *   例: `XBOX_360_For_Windows.ini` (汎用コントローラの場合)
*   **サニタイズ処理**:
    *   DirectInput等から取得したデバイス名に含まれるOSの禁則文字 (`\`, `/`, `:`, `*`, `?`, `"`, `<`, `>`, `|`) は、全てアンダースコア (`_`) にプログラム上で自動置換してファイル名とする。

## 3. 業務フローと責務分担

本アーキテクチャでは、**「`main_app` がファイルの存在と初期状態を保証（作成）し、`core_dll` が実際の値の修正（書き込み）とインゲームへの適用を行う」** という形で責務を分割します。

### 3.1. main_app 側（CLIホスト）の責務：ファイルの初動保証
1.  **デフォルトファイルの作成**:
    *   **キーボード設定（`Keyboard.ini`）**: ハードウェア接続状況に関わらず、標準（デフォルト）構成として常に存在確認・読み込みを行い、存在しなければ標準設定で作成する。
    *   **汎用コントローラ設定（例: `XBOX_360_For_Windows.ini` 等）**: DirectInput等を通じて実際にOSから認識できるデバイス名称を動的に取得し、そのサニタイズされた名称のINIファイルが存在するかチェックする。
    *   存在しない場合のみ、初期バインド構成を記述したファイルを**新規作成（初期化）**する。
2.  **制約事項**:
    *   `main_app` 側では、ファイルから設定を読み込むのみに留め、ユーザーのキーコンフィグ操作による上書き変更（修正処理）は行わない。

### 3.2. core_dll 側（インジェクト先）の責務：実利用と修正更新
1.  **確実なパス解決とロード**:
    *   DLLがゲームのプロセス(MBAA)にアタッチされ初期化される際、DLL自身のモジュールパス(`GetModuleFileNameA`)から絶対パスを算出して `cccaster/` フォルダへアクセスする（相対パストラブルの回避）。
    *   `main_app` によって既に存在が保証されている各デバイスのINIファイルを読み込み、メモリ上の入力フックシステム(`DirectInputHook`)に適用する。
2.  **OverlayUI経由での動的「修正」**:
    *   インゲーム中にユーザーがオーバーレイUIを開き、「ボタンコンフィグの変更」を行った場合、直ちにメモリ上のマッピング情報を更新する。
    *   同時に、該当コントローラの構成INIファイルに対し、**変更された状態を上書き保存（修正）**する。
3.  **例外ハンドリング**:
    *   インゲーム中にファイルアクセスの例外やパース失敗が発生した場合でも、例外を外（MBAA.exe本体）へ漏らさず、安全なデフォルト値へフォールバックしてゲームのクラッシュを防ぐ。

## 4. この設計によるメリットとリスク軽減
*   **同時アクセスの回避**: `main_app` は起動前の準備・作成のみを行い、実際の実行中（あるいは設定変更中）の頻繁な読み書きは `core_dll` 内の単一プロセスで完結するため、ファイルロックの競合リスクが大幅に低減される。
*   **カプセル化**: キーコンフィグ登録の複雑なUI処理やPolling処理をCLI(`main_app`)側に持たせず、実際のDirectInputを触っているゲーム側(`core_dll`)に一任できるため、実装がクリーンになる。
