# レガシーCCCaster ネットプレイ・キャラクターセレクト同期 ワークフロー設計書

## 1. 概要
本ドキュメントは、CCCaster_v10において「CLI画面でネットプレイ（Host/Client）を選択し、ゲーム起動後、バーサスモードのキャラクター選択画面へ遷移して同期を確立する」までの流れを、旧CCCasterの処理構造（レガシーワークフロー）に則って設計したものです。

## 2. 状態推移モデル (NetplayState)
レガシー実装で使用されていた `NetplayState` のうち、キャラセレ遷移に関わる部分は以下の通りです。
1. **`Unknown` / `PreInitial`**: 通信確立待ち、およびゲームプロセスの初期化フェーズ。
2. **`Initial`**: ゲーム起動直後。タイトルメニュー等を自動スキップしている状態。
3. **`CharaSelect`**: バーサスモードのキャラクター選択画面へ到達し、入力のネットワーク同期が開始された状態。

## 3. ワークフロー詳細 (CLI選択〜キャラセレ同期まで)

### フェーズ1: CLIでの通信確立とゲーム起動 (Appレイヤー)
1. **Host/Client 選択**: ユーザーがCLIメニューからホスト待機、またはクライアント接続を選択する。
2. **UDP通信の確立**: `Network` モジュールがP2P接続を確立し、Ping/Jitterの計測を開始する。
3. **ゲームプロセスの起動・インジェクト**: まだ MBAA.exe が起動していなければ起動し、`cccaster_hook.dll` をインジェクトする。
    - すでに起動済み（トレーニングモード等）の場合は、ゲームをリセット（タイトルへ強制送還）して状態を初期化する。
4. **初期状態のセット**: DLL側の同期マネージャー（`RollbackEngine` / `NetplayManager`相当）に対し、現在の状態を `NetplayState::Initial` に設定する。

### フェーズ2: ファストブートと画面遷移の隠蔽 (GameInterfaceレイヤー)
1. **描画のスキップ**: `NetplayState::Initial` 状態では、ユーザーに不要なメニュー遷移を見せないため、ゲームの描画フラグ（`CC_SKIP_FRAMES_ADDR` 等）を操作し、画面をブラックアウトまたは暗転状態で固定する。
2. **強制メニュー遷移 (Fast Boot)**:
    - 毎フレーム監視ループにおいて、ゲームモード（`CC_GAME_MODE_ADDR`）を確認。
    - ロゴ、タイトル画面、メインメニューを自動的かつ最速で突破するため、ダミーの「決定ボタン（Enter）」入力を送り込み、**バーサスモード（Versus）**を選択させる。
3. **到達検知**: ゲームモードが `MODE_CHARA_SELECT (20)` に切り替わったことをメモリから検知する。

### フェーズ3: キャラクターセレクトの同期開始 (Syncレイヤー)
1. **状態の移行**: モードが `MODE_CHARA_SELECT` になった瞬間、DLL内のステートを `NetplayState::CharaSelect` へ移行させる。
2. **インデックスの更新**: 異なる画面の過去の入力が混ざるのを防ぐため、同期フレームの管理単位（`IndexedFrame` の `index`）をインクリメントし、フレーム(`frame`)を `0` にリセットする。
3. **描画の再開**: 画面のスキップ設定を解除し、両プレイヤーの画面にキャラクター選択画面を表示させる。
4. **入力の送受信と反映**:
    - **入力マスク**: キャラセレ画面特有のバグ（決定とキャンセルを同時連打するとゲームがフリーズする等）を防ぐため、特定の不正入力をローカルでマスクフィルタリングする（レガシーの `getCharaSelectInput` 処理）。
    - 自身のコントローラー入力（ディレイ適用済み）と、ネットワーク越しに受信した相手の入力（`PlayerInputs` パケット）を結合する。
    - 結合したP1/P2の入力を `CC_PTR_TO_WRITE_INPUT_ADDR` に書き込み、互いの画面でカーソルが同期して動く状態を確立する。
